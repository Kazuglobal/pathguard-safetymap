| 実測事実（突出分析） | 制作ルール |
|---|---|
| 突破した2本だけが **スキップ率≤0.36 ＋ 維持率≥44%**。維持率37.7%でもスキップ0.539なら115再生止まり | **冒頭3秒が最優先**。冒頭を先に作り、本編はその後に組む |

| 70秒・維持53% → 総視聴時間62時間 | 60〜70秒でも可。ただし **山を3つ**（答え→理由→もう1つの事実） |

## 2. タスクA: 〇倍ギャップの発掘（データ集計）

### 2-0. 着手前（必須）
1. `HANDOFF_CLAUDE_CODE.md` を読み、構成・勝ちパターン・ファイル構造・制約を確認。本ファイルと食い違えば HANDOFF を優先し、本ファイルを直す。
2. `episodes.json` の EP01〜EP20 を全件読み、**比べた軸の組（例: 天候×晴/雨）と結論**を一覧にする。同じ組・同じ結論の言い換えは重複扱い。
3. CSV の見出しを確認。`to-degree` 版は見出しに置換文字（文字化け）が入っていることが分かっている（accident-rankings.md）。**文字化けした見出しや列の位置を推測して読まない**。警察庁の原本 `honhyo_2023.csv`（Shift_JIS）と定義書で列を照合する。照合できなければ集計を止めて報告する。

### 2-1. 「〇倍」の定義（固定）
- 主の指標: **致死率 = 死亡事故件数 ÷ 人身事故件数**（本票1行＝1事故。死亡事故＝`死者数`≥1）。
- 〇倍 = 条件Aの致死率 ÷ 条件Bの致死率。台本には**分母（何件中何件）**を必ず残す。
- 件数の倍率（「AはBの3倍多い」）は、時間の長さや交通量の差で簡単に説明できてしまうので、主の指標にしない。使う場合は「件数」と明記する。
- 採用条件（全部満たす）:
  - A・Bとも人身事故 ≥1,000件、かつ死亡事故 ≥30件
  - 倍率 ≥2.0倍（小数第1位で表示。四捨五入で2.0にしない）
  - 2群の割合の差の検定 p<0.01（または95%信頼区間の下限が1.5倍以上）
  - 地名なし。視聴者の誰もが当事者になる
  - 逆直感の要素がある、または「知らなかった」と言える数字
  - EP01〜20と重複しない
- 交絡の注意: 「夜は致死率が高い」は速度・歩行者・飲酒の影響が混ざる。台本の「理由」パートでは**データで確認できたことだけ**を言い、原因は「〜と考えられる」に留める。

### 2-2. 探索する軸（いずれも仮説。結果はまだ出ていない）
コード表と本票にある列だけを使う。どの組み合わせもまず集計し、採用条件で絞る。

| 軸 | 列 | 比較の例（仮説） |
|---|---|---|
| 道の形 | 道路形状 | 単路カーブ vs 交差点 / トンネル vs その他の単路 / 踏切 |
| 信号 | 信号機 | 施設なし vs 3灯式 / 点滅 vs 点灯 |
| 歩道 | 歩車道区分 | 区分なし vs 防護柵あり |
| 道幅 | 車道幅員 | 広い単路（13m以上） vs 狭い単路 |
| 地形 | 地形 | 非市街地 vs 人口集中地区 |
| 明るさ | 昼夜 | 夜−夜 vs 昼−昼 / 薄暮（昼−暮・夜−暮）vs 昼 |
| 路面 | 路面状態 | 凍結・積雪 vs 乾燥（逆の結果もありうる） |

## 4. タスクC: Three.js 縦動画（動きを増やす）

### 4-1. 方針
- 1080×1920、30fps、60〜70秒。**1本のテンプレートを episodes.json の1件で動かす**（数字を動画のコードに直接書かない）。
- 書き出し: Playwright（入っている Chromium）でページを開き、**フレームごとに時刻を進めて**撮る（リアルタイム再生を録画しない）→ ffmpeg で mp4（H.264, yuv420p）。音声は別に用意する。
- Three.js は `package.json` 既存の `three@^0.181.1` を使う。新しいライブラリは入れない。
- 文字: Noto Sans JP（太字）をキャンバスに描いてテクスチャにする。Reels の UI に隠れない位置: 上220px・下380px・右120px には主要な文字を置かない。

### 4-2. 構成（各秒数は目安）
| 時間 | 山 | 画面と動き | 狙い |
|---|---|---|---|
| 0.0–0.6s | 掴み | 黒から即、問いの一文が**1文字ずつ叩きつけるように**表示（字幕を下からではなく画面中央に大きく）。カメラは速く前へ寄る | 0.5秒以内に何かが動く＝スキップさせない |
| 0.6–3.0s | 問い | 2本の光の柱（条件A・B）が地面から伸びかけて**途中で止まる**。中央に「？倍」が脈打つ | 答えを伏せた未完の問い |
| 3–12s | 前振り | 柱のまわりに粒子（1粒＝N件の事故）が降り積もる。うち死亡事故の粒だけが赤く光る。カウンターが数え上がる | 分母の大きさを見せる |
| 12–18s | **山1: 答え** | Bの柱が先に確定 → Aの柱が一気に伸びてBを追い越す → 「×2.7」（実数値）が衝撃波と一緒に出る。カメラが下から見上げる | 最大の見せ場 |
| 18–40s | **山2: 理由** | カメラが柱の間を回り込み、理由の数字（データで確認できたもの）を順に板として浮かべる。1枚ごとに位置と向きを変える | 中だるみさせない |
| 40–58s | **山3: もう1つの事実** | 場面を切り替え（夜/道/天候などに合う背景色・霧・光）、補足の数字を同じ柱の形で短く見せる | 2つ目の驚き |
| 58–66s | 締め | 粒子が集まって一文になる:「〇〇へ送って」 | シェアを生む |
| 66–70s | 出典 | 小さく出典表示 | 信頼 |

- 冒頭の型を2種作る（**型1: 文字を叩きつける / 型2: 柱が伸びて止まる映像から**）。EPごとにどちらかを割り当て、スキップ率で比べる。
- 演出に使ってよい数字は episodes.json にあるものだけ。架空の数字・飾りの数字は出さない。

### 4-3. ファイル構成（案）
```
artifacts/series-20/threejs/
  index.html          # ?ep=EP21&hook=1 で1本を表示
  scene.js            # 柱・粒子・カメラ・文字。時刻 t を入れると1フレームが決まる（乱数は種を固定）
  timeline.js         # 4-2 の秒数表
  render.mjs          # Playwright で全フレームを撮り ffmpeg で mp4 にする
  out/                # 書き出し先（git に入れない）
```

### 4-4. 確認
- 3本（EP21・EP25・EP30）を書き出し、0s / 0.5s / 3s / 15s / 60s の静止画を見て、文字の欠け・UI に隠れる位置・数字の取り違えがないか確認する。
- mp4 の長さ・解像度・fps を ffprobe で確認する。
