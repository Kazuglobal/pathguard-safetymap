## 1. 二つの資料の勝ちパターンをどう合わせるか

HANDOFF の型（参考の青バー vs ワースト3、30〜38秒）と突出分析（「魔の時間」5,997再生）は、一部が食い違う。シリーズ20の ep01（単独事故）は 348再生・スキップ率0.543 で、突破の目安（≤0.36）に届いていない。そこで **形（episodes.json の項目・ランキングの見せ方）は HANDOFF を守り、フック・キャプション・締めは突出分析に合わせる**。

| 項目 | HANDOFF / 既存EP | EP21〜30 で採用する形 | 根拠 |
|---|---|---|---|
| テーマの形 | 参考（青）vs ワースト3 | **そのまま** | テンプレートとJSONの項目がこの形 |
| 尺 | 30〜38秒、原稿145〜165字 | **そのまま**（既存は約190字なので、短くする） | HANDOFF |
| フック | 「『単独事故』の方が16倍死ぬ」＝条件と倍率を両方出す | **倍率は出して、条件は伏せる**。例「車同士より16倍死ぬ事故がある」。`hookLine1/hookHighlight/hookLine2` に第1位の名前を入れない | 突出分析: 答えを伏せた問いだけが突破 |

## 2. タスクA: 〇倍ギャップの発掘（データ集計）

### 2-1. 「致死率」の定義（既存EPと同じ）
- 致死率 = 死亡事故件数 ÷ 人身事故件数（本票1行＝1事故。死亡事故＝`死者数`≥1）。
- 〇倍 = ワーストの致死率 ÷ 参考の致死率。既存EPと同じく小数第2位までの%で表示し、倍率は「約○倍」。
- 最初に既存EPの数字を1つ再現して定義を確かめる: **EP01 車同士 0.36%・車両単独 5.78%、EP20 全体平均 0.85%**。合わなければ集計を止めて理由を調べる。

### 2-2. 採用条件
- 参考（青バー）: 人身事故 ≥1,000件。件数が多く「安全そう」に見える区分。
- ワースト各バー: 人身事故 ≥200件 かつ 死亡事故 ≥10件。`note` に「○件中○件死亡」または倍率を書く。
- 第1位の倍率 ≥2.0倍。差が統計的に有意（2群の割合の検定 p<0.01）。
- 地名なし。視聴者の誰もが当事者になりうる。
- 下の「使用済みの軸」と重複しない。

### 2-3. EP01〜20 で使用済みの軸（重複させない）
事故類型（01, 20）/ 昼夜（02）/ 道路形状（03, 20）/ 歩行者×時刻（04）/ 自転車×時刻（05）/ 曜日（06）/ 当事者A の車種（07）/ 75歳以上×事故類型（08）/ 月（09）/ 信号機（10）/ 交差点の幅員（11）/ 24歳以下×時刻（12）/ 道路線形（13）/ 中央分離帯（14）/ 路面状態（15）/ 歩車道区分（16）/ 祝日（17）/ AT・MT（18）/ 年代（19）

「同じ軸で、対象（歩行者・自転車・年代など）を変えただけ」のものは、結論が新しい場合だけ採る（例: 04・05・12 はどれも「時刻」だが対象が違う）。

### 2-4. まだ使っていない候補（どれも仮説。集計で確かめる）
- コード表にある項目: **天候**（霧・雪 vs 晴）、**地形**（非市街地 vs 人口集中）、**ゾーン規制**（ゾーン30 vs 規制なし）、**単路の幅員**（広い道 vs 狭い道）、**当事者B の種別**（相手が何だと死にやすいか）
- 原本のコード表が必要な項目: **速度規制**、**衝突地点/車両の衝突部位**（正面 vs 側面 vs 追突）、**一時停止規制**、**エアバッグ**、**サポカー**
- 掛け合わせ: 曜日×時刻（土曜深夜 vs 平日朝）、車種×場所（二輪×カーブ、軽自動車×単独）、天候×昼夜（雨の夜 vs 晴れの昼）

## 4. タスクC: Three.js 縦動画（動きを増やす）

### 4-1. 方針
- `artifacts/series-20/threejs/`。episodes.json の1件で1本が動く（数字をコードに書かない）。EP01〜20 の実データで先に作り、EP21〜30 にそのまま使う。
- 1080×1920・30fps。尺は `audio/epXX.wav` があればその長さ、なければ36秒。
- 書き出し: Playwright でページを開き、`renderAt(t)` で**フレームごとに時刻を指定して**撮る → ffmpeg で H.264 / yuv420p。リアルタイム再生を録画しない。
- 背景は3Dで作る（暗い道路のグリッド・霧・光の粒）。背景画像は不要。
- 文字は HTML で重ね、3Dの柱の位置に合わせて動かす（日本語をくっきり出すため）。Reels のUIに隠れる範囲（上220px・下380px・右120px）に主要な文字を置かない。
- `three@0.181.1`（package.json の既存依存）。新しいライブラリは足さない。

### 4-2. タイムライン（36秒基準。音声の長さに合わせて伸び縮み）
| 時間 | 山 | 画面と動き |
|---|---|---|
| 0.0–0.5s | 掴み | 黒からいきなり、`hookHighlight` が1文字ずつ叩きつけるように出る。カメラが道路の上を高速で前進 |
| 0.5–3.5s | 問い | `hookLine1/2` が出て、中央に「？」付きの光の柱が地面から伸びかけて止まる |
| 3.5–9s | 参考 | 青い柱（参考）が伸び、数字が数え上がる。粒子が降り積もる |
| 9–14s | 第3位 | 金の柱が伸びる。カメラが横へ回り込む |
| 14–19s | 第2位 | 赤の柱が伸びる。カメラが少し引く |
| 19–24s | **第1位** | 柱が画面を突き抜ける勢いで伸び、カメラが下から見上げて追う。赤いフラッシュ・画面の揺れ・衝撃波の輪・粒子の破裂。「約○倍」の巨大な文字 |
| 24–30s | 理由 | 2枚の板（`reasonLeft/Right`）が左右から回転しながら飛び込む |
| 30–34s | 締め | 粒子が集まって `ctaTitle` になる |
| 34–36s | 出典 | 「出典：警察庁 交通事故統計オープンデータ（2023年）」 |

上部には常に `FILE #XX // caseTitle` と経過タイマー（HANDOFF の HUD）を表示する。

### 4-3. 確認
- 0s / 0.5s / 3s / 12s / 21s / 27s / 33s の静止画を見て、文字の欠け・UIに隠れる位置・数字の取り違えがないか確認。
- ffprobe で長さ・解像度・fps を確認。
