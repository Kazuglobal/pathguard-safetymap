## 使い方

1. `_assets/writing-brief.md` — 全記事共通の事実source of truth(機能一覧・禁止事項・スタイルガイド)。記事を手直しする際は必ずこれと矛盾しないか確認する
2. `_assets/research/` — 自己検証の元データ(note攻略・読者インサイト・個人開発バズパターン・検証済み統計)
3. `articles/NN-slug.md` — 記事本文。frontmatterの `publish_priority` が公開推奨順(数字が小さいほど優先)
4. `articles-v1-backup/` — 2026-07-12版(29本)。比較用。**年次の誤記を含むので流用しないこと**
5. 公開前に必ず: (a) `https://〔LPのURL〕` を実際のLP URLに置換 (b) 本文中の画像プレースホルダ(`(▼...)`)に実際のスクショ・図解を差し込む (c) noteに貼る前にもう一度人間の目で通読する

## 「注目される記事」の判定基準(2026-07-12の審査基準を継続)

リサーチ(note攻略・保護者インサイト・個人開発バズパターン)から導出し、審査員パネルの採点基準にした12項目:

1. タイトルが20〜35字で、数字・固有名詞・ギャップ・ベネフィットのいずれかを含み、煽り・誇大表現がない
2. 一次体験・検証を自分の言葉で語れる題材か(知識の羅列や一般論の翻訳だけになっていないか)
3. 冒頭3行で「誰のための何の話か」を宣言できる、想定読者が1人に絞れているか
4. 読者の実在する悩み・検索行動に対応しているか(「書きたいこと」でなく「読者が悩んでいること」起点か)
5. 統計はr4「使用可」のみで出典を本文に明記でき、恐怖で煽らず「今日できる小さな行動」で閉じられるか
6. チェックリスト・手順フロー・意外な学びなど、見返したくなる保存価値があるか
7. 季節・時期の不安の波と公開タイミングを一致させられる企画か
8. 地図スクショ・AI判定画面・図解など、記事内で完結するビジュアル素材を用意できるか
9. ブリーフの実装済み機能・事実のみで書き切れるか(誇張・捏造・断定的実証がない)
10. 共感トリガー、または健全な議論性が明確か
11. プロダクト導線が売り込みでなく文脈の必然として置けるか
12. dev系・体験系は「動機→挫折→転機→結果→学び」のアークに乗るか
