# 取得時点の道路形状を使う全国集計規則 v1

規則の条件を固定するための文書。採用台帳・改訂集計・地域関係の全件検証と実画面確認が終わるまで、本番公開の承認とは扱わない。旧候補の `reviewed:false` は保持し、採用根拠を別の版管理台帳に保存する。

## 地点の条件

交差点は同じOSMノードで4接続があり、接続の立体区分に競合がない単位に限定する。道路区間は両端が3または4接続の交差点で、元ノードで復元した内部の接続数がすべて2、途中で立体区分が変わらない単位に限定する。正常な形状と検証済みの行政区域を持つことも必要とする。

`layer=0, bridge=no, tunnel=no` には、OSMに値がない場合の既定値を含む。原タグの有無を保存し、「現地の地上構造を独立に確認済み」とは呼ばない。地図上で線が交差していても元ノードを共有しない道路は接続しない。近接したノードを距離だけで統合しない。

環状交差点、接続リンク、motorway/trunk、oneway、分離車道の指定、橋・トンネル・非地上層・covered/locationの構造指定、道路区域、内部の分岐や構造切替を持つ単位は保留する。onewayは分離車道の証明ではなく、今回の限定規則で疑いを保留する指標として使う。OSMに記録のない物理的な交差点まで不存在を証明したとは表示しない。

## 事故を数える条件

交差点への候補距離30m、道路への候補距離20mを用いる。交差点10/20/50mの比較は別の方法評価として保持する。元事故の市区町村と地点の市区町村が一致し、地域対応に未解決がなく、候補が構造的に1つで、追加の形状・立体・非接続道路の競合がない事故だけを1地点へ割り当てる。

候補競合・地域未解決・地点保留は未確定として残す。同じ付近の別事故を重複として削除しない。原事故の識別・年度・時間帯・当事者・死亡事故・事故の種類は既に全原事故を再構成して照合した条件を保持する。

公開する表現は「取得時点のOSM形状で場所を確認できた事故件数の多い順」。全事故の確定順位、事故に遭う確率、事故当時の道路構造、現地確認済みとは表示しない。確認できない場所を除いたことと、対象期間・未確定・対象外・方法の版を表示する。

## 外部資料との対応

柏・札幌・糸満・三沢・昭島・春日の交差点と、市川の道路区間の計7適合例を、元ID、形状SHA、原接続、原タグ、地理院地図の画面SHA、観察、適用条件へ結び付ける。明石の5接続と神戸の構造切替を保留例に結び付ける。三沢・昭島・春日は保存画像を改めて確認し、中心の4道路腕と近隣交差点が別であることを記録した。

この確認は限定規則の評価であり、全国の精度や誤り率を推定する標本ではない。取得時点のOSM形状を過去の事故座標に重ねる方法であり、全事故年度の道路網を復元する条件は追加しない。

## 採用版と公開成果物

元タグ監査の出力は265,378 ID、適合候補205,695 ID、保留59,683 ID。独立検証が成功した版だけを採用台帳の入力にする。内部例外895 IDも保留理由を保持する。事故側の候補競合と地域未解決は、この地点規則を通っても別に未確定へ残す。

改訂版は全原事故2,182,298件について、割り当て済み＋未確定＋対象外を照合する。保留へ戻した事故だけを差分として追跡し、原識別と条件は変えない。地域関係は既存の元地域・現在候補の和集合を保持し、新たな未確定事故へ検証済みの元市区町村の関係を1件加える。全国総数は地域関係の総和ではなく原事故で数える。

公開用には集計6表だけを分離し、原事故識別や監査用の詳細をAPIへ出さない。出典・取得日・対象年・利用条件・帰属・入力出力SHA・正常終了・全件照合・採用台帳の版を記録する。空の出典、`candidateOnly:true`、未完了の地域方式や公開ゲートのまま公開しない。

実データで全国と千葉県→柏市→自転車→地点詳細、地図同期、戻る／共有、空表示、再試行、スマートフォンを確認する。最新mainのPR #250とCIを経て、mainのCloudflare Production GitHub Actionsだけで公開し、公開後の確認を行う。
