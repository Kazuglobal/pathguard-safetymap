  - `*.city.*.jp`（市区町村の防犯情報・安全メールアーカイブ）

- これが通れば、**11章-1 の「単一ソース問題」も、第2経路を自力で取れるようになることで実質的に解消する。**

### 3. 【2回連続・修正提案】`formatNewsDate` が JST ではなくローカル時刻で日付を出している

```ts
// lib/school-route-news-feed.ts
export function formatNewsDate(dateString: string): string {
  const date = new Date(dateString)
  return `${date.getFullYear()}.${String(date.getMonth() + 1).padStart(2, '0')}.${String(date.getDate()).padStart(2, '0')}`
}
```

- **UTC で動くサーバ／ビルドでは、JST 07:00 公開の記事が常に「前日」として表示される**
- 「毎朝7:00更新・7:30ダイジェスト」という**デイリーハビット設計の根幹（トリガーの固定）と矛盾する**
- **修正案**: 同ファイルに既存の `toJstDateKey` と同じ JST 固定の導出に揃える。`Intl.DateTimeFormat('ja-JP', { timeZone: 'Asia/Tokyo' })` でも可
- **本PRでは修正していない**（日次更新の範囲を超え、全記事の表示に影響するため）。**別PRでの修正可否の判断をお願いしたい**

### 4. 【継続・修正提案／6回連続】`uses generated artwork` テストのタイムアウト

既定5秒のタイムアウトで、冷えたCI環境では173ファイルの読み込みとmd5計算が超えうる。`it(..., { timeout: 30000 })` を付けるだけで解消できる。**今回は画像不在による即時エラー（ENOENT）のためタイムアウトは観測されていない。**

### 6. 【新規・運用の確認】実行時刻が JST の日付境界をまたいでいる

本セッションの実行ウォールクロックは **2026-11-08 05:33 JST**（システム日付は UTC の 2026-11-07）。

- デイリーハビット4原則の第1は「**更新は毎朝7:00に完了させ、7:30のダイジェスト通知に間に合わせる**」である。05:33 JST 着手は**間に合う時刻**だが、**スケジュールが UTC 基準で組まれているため、日によって JST の実行時刻がずれる**
- 本セッションでは、ブランチ名・レポート日付・`publishedDate` を**従来どおりシステム日付（2026-11-07）で統一**した。記事の `publishedDate` は 2026-11-07T07:00〜07:10+09:00 であり、**実行時点（11-08 05:33 JST）より過去**になっている
- **確認をお願いしたい**: スケジュールのトリガー時刻を **JST 06:00 前後に固定**するか、あるいは**レポート日付・`publishedDate` を JST 基準に切り替える**か。現状は「UTC日付のラベル」と「JSTの実運用時刻」が1日ずれうる
