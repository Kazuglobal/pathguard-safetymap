## 4. Step 5: 画像（スケジュールプロンプトの指示と実装の矛盾・8回連続）

### 4-a. 指示どおり `thumbnailUrl` を省略すると検証ゲートが必ず赤になる

スケジュールプロンプトは「`thumbnailUrl` フィールド自体を書かない（省略する）。型は optional で、release-readiness テストも未設定ならスキップするため検証は緑になる」としている。**この前提は `main` の実装と一致しない。**

`tests/unit/lib/school-route-news-release-readiness.test.ts` には**2つの別々のテスト**がある。

| テスト | 挙動 | 省略した場合 |
|---|---|---|
| `references only existing thumbnail files`（123行目） | `if (!item.thumbnailUrl) continue` | **スキップされる**（プロンプトの前提どおり） |
| `thumbnail coverage > gives every news item a thumbnailUrl whose file exists`（141〜147行目） | `expect(item.thumbnailUrl).toBeTruthy()` | **必ず失敗する** |

プロンプトが根拠にしているのは前者の挙動であり、**後者の存在が考慮されていない**。`thumbnailUrl` を省略すると、同じプロンプトが要求する **Step 7（緑になるまで完了と言わない）を構造的に満たせない。**

### 4-b. 本実行の対応

**暫定のプレースホルダー画像を slug ごとに新規生成し、`thumbnailUrl` を設定した。** 2つの指示が衝突したとき、**「検証ゲートを緑にする」ほうを優先した**（プロンプトが完了条件として明示しているため）。**前回・前々回と同じ判断であり、運用の一貫性も保っている。**

プロンプトの禁止事項には抵触していない。

- **「存在しないPNGのパスを書く」**: していない。**3件すべてファイル実在を機械検査済み**
- **「他記事の画像の流用」**: していない。**3件とも新規生成**し、**既存88ファイルを含む全91ファイルでMD5衝突0件**を機械検査済み

生成方法: **ImageMagick の描画プリミティブ**（`convert` の `-draw`）で 1200×630 の抽象画像を生成した。**この環境の Python PIL は `_imaging` 拡張が壊れており使用できない**（`ImportError: cannot import name '_imaging'`。D-16 が2回連続で再現）。Step 5 の表現指針に沿い、**事故現場・不審者本人は一切描いていない**。横断歩道のストライプ・黄色い帽子のシルエット・光だまりという抽象モチーフを、**カテゴリカラー**（accident=赤／suspicious=オレンジ／policy=紫）で描き分けている。

**これはAI画像生成による本番サムネイルではない。** PR本文の冒頭に、マージ前の差し替えが必要である旨を明記した。
