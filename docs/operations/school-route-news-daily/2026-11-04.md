### 5-a. 【重要】プロンプトが案内する手順は、この順序では実行できない

PR本文にも書いたが、プロンプトの【存在しない場合】は「`npx tsx scripts/generate-missing-images.ts news` を実行して画像を生成し、`thumbnailUrl` / `contentImages` を追記する」と案内している。**この順序は動かない。**

実測（Step 7）:

```
参照画像 88 件 / 欠落 0 件（モデル候補: 2 種）
```

スクリプトは**「参照されているのに実ファイルが無い画像」だけを埋める**。`thumbnailUrl` を書いていない記事は参照が0なので、**何も生成されない**。正しい順序は逆である:

1. 先に `thumbnailUrl: "/images/school-route-news/thumbnails/shiojiri-schoolway-joint-inspection-20261104.jpg"` を記事に**書く**

### 8-f. 【新規・要判断】表示日付が JST ではなく実行環境のローカル時刻で出ている

`lib/school-route-news-feed.ts`:

```ts
export function formatNewsDate(dateString: string): string {
  const date = new Date(dateString)
  return `${date.getFullYear()}.${String(date.getMonth() + 1).padStart(2, '0')}.${String(date.getDate()).padStart(2, '0')}`
}
```

`getFullYear/getMonth/getDate` は**実行環境のローカルタイムゾーン**で評価される。UTCで動くサーバ／ビルドでは、**JST 07:00 公開の記事が「前日」として表示される**。

- **すぐ下に正しく JST へ丸める `toJstDateKey()` が既にある**ので、修正は容易とみられる

**本PRは内容更新のためスコープ外として手を入れていない。** 別PRで直してよいか判断をお願いしたい。**「毎朝7:00に更新し7:30に通知する」という設計の記事が前日の日付で出るのは、デイリーハビットの根幹（トリガーの固定）に関わる。**

# 追記（2026-11-05 JST・同セッション内）: 画像生成を恒久的に解決した

上記 11章-1 で「16回連続の申し送り」としていた画像の問題について、ユーザーから

## A. 根本原因は `.gitignore` だった

`.github/workflows/school-route-news-images.yml` が「存在しない」状態が続いていた原因が判明した。

```
.github/*
!.github/workflows/
.github/workflows/*

```

`.gitignore` が `.github/workflows/*` を**許可リスト方式で除外**している。
そのため**新規ワークフローを追加しても git が黙って無視する**。
実際、PR #253（2026-10-15）で同名のワークフローが作られ Actions 上で3回実行されているが、
main には入っていない。許可リストに1行追加して解消した。

**次回以降、`.github/workflows/` に何か足すときは `.gitignore` の許可リストも必ず更新すること。**

## C. 5-a で書いた「順序が逆で実行できない」問題は解消した

`ensure-news-image-refs.ts` を前段に置くことで、`thumbnailUrl` の書き忘れがあっても
参照が自動で補われ、生成対象になる。実測:

```
（参照を埋める前）参照画像 88 件 / 欠落 0 件   ← 何も生成されない
（参照を埋めた後）参照画像 91 件 / 欠落 3 件   ← 生成対象になる
```
