# PathGuardian 構想の吟味・根拠・調整点

確認日：2026年10月10日（日本時間）  
版：0.2  
対象：共有された事業構想、D-001〜D-039の回答、ユーザー提供の通学路交通安全対策一覧表PDF。

## 1. 構想の核

採用する核は、危険情報を集約し、関係者が確認し、改善案件へつなぎ、対策と効果を記録し、地図・報告・教育へ還元する循環である。

初版の価値仮説は「職員・学校関係者が、危険箇所の受付、担当調整、進捗確認、年度更新、資料作成にかける負担を減らせる」。事故減少は長期的な目的であり、90日の業務実証だけで因果効果を断定する指標にはしない。

## 2. 今回調整した点

| 元資料の表現・前提 | 調整 | 理由・設計への影響 |
| --- | --- | --- |
| 4領域を共通の危険地点データベースでつなぐ | 行政用を別製品とし、データ・権限を分離。許可された危険情報だけを連携 | D-001・D-002。家庭データへ行政が直接アクセスできる構成は採用しない |
| 7つの主要機能を段階開発 | 行政用初版は受付・改善管理・地図／報告書を完成目標にする | D-003。予測・教育・現地装置は将来接続する領域として保持 |

| 個人情報を極力持たない | 児童・家庭の情報を最小化し、職員アカウント等の必要情報は目的・保存・権限を定義 | 氏名や連絡先を一切持たない、という未達の約束を避ける |
| 初版の地図・帳票が幅広い候補のまま | A4安全マップ、A3横の対策一覧表、CSVを必須出力にする | D-029・D-033。別の改善要望書・対策報告書は初版必須にしない |
| 対策一覧の1行・1結果記号で案件を表す | 1行＝要望案件を維持し、複数対策の結果を併記 | D-012〜D-014。要望不採用と代替対策完了を同一の○×へ集約しない |
| 公開・連携・配布の許可が曖昧 | 投稿ごとの行政共有、本人返却、家庭配布を別に管理 | D-018〜D-020・D-039。家庭用は行政承認、関連変更で旧版停止・再承認・訂正案内 |

| 30%短縮・90日等の数値案 | 業務一巡と工数計測を採用し、削減率は基準測定後に設定 | D-037。協力先、開始日、期間、人数は未合意 |

この表で決定IDを示した方針は会話の回答に基づく。具体的な状態、操作、構成の細部は設計提案であり、未回答の運用ルールまで承認されたとは扱わない。[決定台帳](./decision-log.md)と[未決事項](./questions-and-tasks.md)を参照する。

## 3. 一次資料で確認した事実

### E-001：柏市の通学路安全対策

柏市の公開資料には、関係機関による点検、対策、効果把握、継続改善の流れと、学校別の対策一覧の公表が記載されている。参照PDFの表紙は令和7年8月改訂版。担当部署の日々の操作、利用システム、紙・Excelの割合は、この資料だけでは確定できない。

設計への反映：学校単位の一覧、複数の対応機関、点検・対策・効果確認の記録を扱う。現行業務の置換範囲はT-001で調べる。

出典：[柏市 通学路交通安全対策プログラム](https://www.city.kashiwa.lg.jp/documents/5910/kashiwashikoutuuanzentaisakupuroguramu.pdf)

### E-002：警察庁の事故オープンデータ

公開ページで2019〜2025年のデータへのリンクを確認した。概要によれば対象は死亡・負傷を伴う交通事故であり、本票は1事故1レコード、補充票は追加の当事者に関する別レコードである。事故数の集計に両者を単純加算しない。公開時点後の判明事項により他の統計表と相違し得ることも説明されている。

設計への反映：利用年度、票種、コード表の版、取込元を記録し、履歴の網羅性を過大表示しない。対象外の事象をゼロと見なさない。

出典：[交通事故統計情報のオープンデータ](https://www.npa.go.jp/publications/statistics/koutsuu/opendata/index_opendata.html)、[交通事故統計データの概要](https://www.npa.go.jp/publications/statistics/koutsuu/opendata/koutsuujiko_opendata_overview.pdf)

### E-003：小学校区データは存在するが、地域別確認が必要

国土数値情報A27のページでは、2023年度版の小学校区データとGeoJSON等の提供を確認した。同ページは自治体別の利用条件、欠損、最新指定との差、位置の誤差に注意し、詳細を自治体へ確認するよう求めている。全国の現在の正式学区をそのまま表示できると扱わない。

設計への反映：データ入手可能性と利用許可を分ける。対象自治体の条件確認、境界照合、版管理を初版の準備項目にする。

出典：[国土数値情報 小学校区データ](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-A27-2023.html)

### E-004：東京海上日動・日本工営の機能は大きく重なる

2025年8月13日の共同発表は、学校・PTAの写真と位置を用いた入力、地図集約、担当部署・対応ステータスの管理、AIリスクマップ、対策結果の蓄積・公開を説明している。価格、API、帳票の細部、現在の導入条件は本調査では確認できていない。

設計への反映：受付・管理・AIを統合するだけでは差別化できると判断しない。既存のPathGuardianからの許可制連携、学校の資料更新、効果記録、導入負担について、顧客が評価するかをT-006で検証する。

出典：[通学路安全点検支援システムの開発（共同発表）](https://www.tokiomarine-nichido.co.jp/company/release/pdf/250813_01.pdf)

### E-005：KDDIも危険地点の分析と対策検討を支援

KDDIは2025年3月26日の発表で、人流・車両等のデータと交通事故統計を使う「交通安全インサイト」の提供開始を説明している。AI予測そのものを独自性とする根拠にはならない。

出典：[KDDI「交通安全インサイト」提供開始](https://newsroom.kddi.com/news/detail/kddi_nr-514_3791.html)

### E-006：事故データを加工した表示の出典

警察庁の現行利用規約は出典の記載、加工したことの表示等を定めている。個別コンテンツの権利や外部データの条件も確認する必要がある。

設計への反映：地図・一覧・PDFに出典、対象年度、加工主体を載せる。利用条件確認の結果をデータセット台帳へ保存する。

出典：[警察庁 利用規約](https://www.npa.go.jp/rules/index.html)

### E-007：提供PDFは複数対策・管轄外等の例外を含む

ユーザー提供PDFの全9ページを文字・表の抽出と画像で確認し、67行の記載を確認した。道路管理者は国・県・市の3列で、危険箇所の所在地と場所説明は別欄。複数対策、一部実施不可、代替対応、私道、隣接市の住所、1要望に離れた2地点、担当欄の空欄が含まれる。

設計への反映：要望、行政回答、個々の対策・結果、機関、場所、年度を分ける。資料中の単一記号を構造化した現在状態へ自動変換しない。公開PDFの掲載数を現在の危険総数・未処理数と扱わない。

出典：[提供PDFの保存コピー](./references/r6tugakurokoutuanzentaisakuitiranhyou.pdf)、[詳細レビュー](./pdf-review.md)、[柏市の掲載ページ](https://www.city.kashiwa.lg.jp/jidoseito/kyouiku/anzen/5910.html)。公式掲載ページの更新表示は2025年8月8日であり、現地の最新状態を示す日ではない。

### E-008：行政の委託データを独自用途に流用しない

個人情報保護委員会の行政機関等編FAQは、委託された範囲を超える自社営業利用、匿名加工後の第三者提供、自社のための統計加工等を許容しないと説明している。委託元による選定、契約内容の確認、監督も説明されている。

設計への反映：行政の内部データを運営者の営業・独自AI学習へ転用する権利を初版に設けない。契約・目的・委託先・保存・運営者アクセスをT-007で具体化する。本文・写真等の加工だけで利用条件がなくなるとは扱わない。対象自治体の法令・規程・契約への適合は未確認。

出典：[個人情報保護委員会 FAQ Q3-1-1](https://www.ppc.go.jp/all_faq_index/faq7-q3-1-1_/)、[行政機関等編ガイドライン](https://www.ppc.go.jp/personalinfo/legal/guidelines_administrative/)

### E-009：Mapboxの日本地図をPDF背景に採用する前に印刷条件を確認する

Mapboxの出典表示資料は、Streets v8以降の日本地図データの印刷について教育・私的用途の条件を記載している。Static／printにも出典表示が必要。Static Images APIは画像出力で、PDFを直接出力するものではなく、指定寸法には上限がある。

設計への反映：行政契約下の家庭配布、内部帳票、配布部数・方法、採用する地図スタイルについて利用条件を照合する。学校用途という説明だけで適用可否を決めない。Mapboxの画面表示を再利用できることと、A4／A3の配布PDFを生成できることを分け、T-003・T-008で確認する。

出典：[Mapbox 出典表示・印刷](https://docs.mapbox.com/help/ja/dive-deeper/attribution/)、[Static and print maps](https://docs.mapbox.com/help/dive-deeper/static-maps/)

### E-010：MFAは認証画面に加えてAPIで強制する

Supabase Authの公式資料は、認証器・電話等によるMFAとJWTの認証強度、画面に加えAPI等への強制を説明している。

設計への反映：D-035の全員MFAは画面の登録だけで完了としない。行政用API、画像、帳票の取得で、検証済みトークンの認証強度と有効な所属・用途を確認する。D1のテナント・学校・案件認可はアプリ側の設計・検証が必要。認証の復旧と所属解除もT-008・T-011で扱う。

出典：[Supabase Multi-Factor Authentication](https://supabase.com/docs/guides/auth/auth-mfa)

### E-011：D1／R2の配置ヒントは日本国内保管の保証ではない

D1・R2の公式資料は、配置ヒントが保証ではないことと、EU・FedRAMP・USのjurisdictionを記載している。D1は読取レプリカの配置にも注意が必要。

設計への反映：既存技術を基本にするD-030から、日本国内限定の保管や自治体調達への適合を推定しない。自治体の必要条件と、業務DB・画像・Auth・ログ・バックアップ・実行場所を照合する。条件を満たせない部分は実証前に構成を再判断する（T-007・T-008）。

出典：[Cloudflare D1 Data location](https://developers.cloudflare.com/d1/configuration/data-location/)、[Cloudflare R2 Data location](https://developers.cloudflare.com/r2/reference/data-location/)

## 5. 既存アプリの資料との関係

## 6. 不明点を増やさない進め方

「事実」「合意」「仮説」「提案」「未確認」を混ぜない。新しい前提が見つかったら質問IDまたは調査タスクIDを作り、影響する仕様と結び付ける。

未発見の論点が存在しないとは保証できない。実務の一巡、権限の否定ケース、資料・写真の例外、障害、引継ぎ、契約終了を順に確認し、発見した不明点を台帳に残さず進めることを防ぐ。
