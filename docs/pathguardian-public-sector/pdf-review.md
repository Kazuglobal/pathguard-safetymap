## 3. 実例から見つかった設計上の論点

次の記述は提供PDFのレビュー用要約であり、現在の現場や対策の妥当性を判断するものではない。

| 参照 | 確認内容 | 必要な設計 |
| --- | --- | --- |
| 1ページ・2-22 | 一つの区間に複数の要望と、不採用の対策・実施する別対策が記載 | 要望を全部実施したかと、採用対策を実施したかを分ける |
| 1ページ・2-23 | 道路管理者と警察が関与。実施困難な要望と、できる対応を併記 | 1案件に複数機関・複数対策。担当有無だけで受諾済みにしない |
| 2ページ・7-24 | 学校所在地と別の市の住所を持つ | 関連学校・学校区と行政管轄を分離。域外住所を自動で対象外にしない |
| 3ページ・14-28 | 一つの要望番号で離れた2地点の標示を扱う | 案件番号と地点番号を分離。複数地点の関連方法はQ-033で決定 |
| 4ページ・16-14 | 私道を理由に市の補修ができない | 管轄外、私有、実施不可、別管理者への依頼を別項目にする |
| 6ページ・27-24 | 希望された対策は不可だが、別の対応が記載 | ×を「何も対応していない」「全対策終了」と自動変換しない |
| 7ページ・30-20 | 担当欄が空欄でも本文に警察の対応への言及がある | 空欄を担当なしへ自動確定しない。本文との相違を確認対象にする |
| 9ページ・柏の葉小の2行 | 左端の数字と箇所番号の接頭辞が一致しない | 左端の数字を正式学校コード・一意キーと見なさない |

文章の「実施予定」と○の記号が併存する例もある。日付や根拠の不足を、抽出処理が勝手に補わない。

## 4. 仕様へ反映すること

1. 行政用一覧表に国・県・市・警察・教委の担当列と、住所・場所説明の別項目を設ける。
2. 1行＝1要望案件、複数対策の結果を併記するという回答を維持する。原票の単一記号を、そのまま複数対策の結果として複製しない。
3. 危険状況、要望、行政の回答、採用対策、実施不可理由、実施記録、残存課題を分離する。
4. 学校・案件・地点・対策・年度・資料版の識別を分ける。資料番号から新しい番号を推測しない。
5. 入力不足のデータは過去資料の記録として保持し、現在の案件管理や家庭配布に採用する前に確認する。
6. 添付PDFに個別家庭の通学経路や、最新の共通通学路の線データが入っているとは扱わない。

詳細な出力設計は[帳票・入力項目仕様](./report-specification.md)、回答と未決事項は[決定台帳](./decision-log.md)と[質問・タスク台帳](./questions-and-tasks.md)を参照する。

## 5. 確認の限界と残タスク

- PDFの内容を実際の行政の現在の案件として登録したわけではない。
- 67行を解析できたことは、自動移行機能が実装・合格したことを意味しない。
- 原資料の単一記号を対策ごとに分けるには、元の回答・実施根拠を担当者が確認する必要がある（T-002）。
- この公開PDFが存在することは、未公開資料の再配布や、採用する背景地図の印刷を許可する根拠にはならない（T-003・T-007）。
- 柏市の協力・採用・導入が決まったわけではない（D-004・T-010）。
