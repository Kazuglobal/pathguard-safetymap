# PathGuardian 行政用アプリ 設計・仕様検討

作成・更新日：2026年10月10日（日本時間）  
版：0.2／回答・実物帳票を反映した草案  
目的：行政用の独立した製品について、構想を吟味し、開発・実証・契約判断に使える仕様へ具体化する。

## 現在の設計

行政用は既存アプリとは別製品とし、1自治体の一部学校から始める。行政・招待学校・PTAが、危険情報の受付、点検、担当調整、複数対策の進捗、年度継続を管理する。既存アプリとは投稿ごとの許可を確認したAPIでつなぎ、家庭別の通学経路・児童情報を連携しない。

必須出力は学校別安全マップのA4 PDF、通学路交通安全対策一覧表のA3横PDFとCSV。家庭配布は行政の指定承認者が承認し、関連情報が変わったら旧版の新規取得・配布を止めて修正版を再承認する。配布済み資料は学校へ訂正を案内する。外部機関との連絡・回答は行政職員が記録する。

全39件の決定は[決定台帳](./decision-log.md)に記録した。詳細な権限・状態・番号・技術・運用の提案まで承認済みという意味ではない。実証協力先は未決で、全国AI予測、一般公開Web、行政用スマホ操作、外部機関専用アカウントは初版の必須範囲にしない。

3. [質問・調査タスク台帳](./questions-and-tasks.md)：回答待ち、決定した方針と残る詳細、確認方法・担当案・完了条件。
4. [決定台帳](./decision-log.md)：D-001〜D-039の回答、根拠、反映先、決定の限界。
5. [提供PDFのレビュー](./pdf-review.md)：全9ページ・67行の確認、実物の列構造と例外、設計への反映。
6. [構想の吟味・根拠・調整点](./review-and-evidence.md)：一次資料、今回のレビュー指摘、調整した設計と未検証の主張。
7. [共有された元テキスト](./source-summary-2026-10-10.md)・[提供PDF](./references/r6tugakurokoutuanzentaisakuitiranhyou.pdf)：原文を維持した保存用コピー。

## 草案と未決事項の扱い

「決定」はユーザーが回答した事項、「提案」は未回答の具体化、「資料上の事実」は原資料から確認した内容、「実証前確認」は協力先や提供者へ照合する条件。公開PDFを確認できたことを、現在の案件状況・実務の効率・実証への協力の証明にしない。

現在の回答待ちはQ-033（1要望に複数場所）、Q-017-G（CSV取込の初版採否）、Q-026-B（体制・予算・希望納期）。次に案件全体の完了・終結条件、番号・空欄・CSVの具体仕様、本人返却の承認等を詰める。実際の保存期間、自治体の端末・保管条件、地図の印刷配布条件、負荷・費用は調査タスクで追跡する。

実在の個人情報を使わないデモを先に確認し、協力先の条件を反映して実証用初版へ進める。未決の費用・納期・保存期間・性能を確定値として書かない。本版は仕様検討用であり、行政用アプリの実装・配備・実証は行っていない。

## 更新と文書確認

質問への回答を決定台帳へ記録し、仕様・帳票・質問の状態を同期する。調査では確認日・一次資料・適用範囲・限界を残す。仕様を確定する条件は仕様書20章に記載した。回答待ちや未調査の条件があるため、確定仕様として開発へ渡す段階にはまだ達していない。

2026年10月10日に8つのMarkdown文書を静的確認した。ローカルリンク38件のリンク切れ、未登録の決定・質問・タスク・要件参照、重複ID、閉じていないコードブロックは0件。39決定、34の基礎質問と枝番、12調査タスクを記録し、20要件と20受入条件、15の開発後検証シナリオへの全要件の対応を確認した。CSV取込等の未決要件は採用済みの要件と区別している。

元テキストとPDFは保存コピーのSHA-256が提供ファイルと一致し、PDFは9ページであることを確認した。これは文書検査であり、アプリの動作試験・実際の帳票生成・実印刷・自治体の導入審査とは区別する。
