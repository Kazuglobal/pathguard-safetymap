# PathGuardian 新規事業構想・これまでの会話の総まとめ

**2026年10月10日時点**

これまでの議論、全国自治体の調査、AI事故予測の先行事例、路面シールの取り組み、そして新しく提案された機能を統合して整理します。

## 1. PathGuardianが目指すもの

### コンセプト

**「事故が起こる前に危険を発見し、地域全体で改善し、子どもたちが楽しみながら安全を学べるプラットフォーム」**

PathGuardianを単なる通学路の危険マップから、全国の自治体・学校・PTA・保護者・子どもをつなぐ総合的な安全プラットフォームへ発展させる構想です。

目指しているのは、次の循環を生み出すことです。

**危険を予測する → 発見する → 共有する → 改善する → 効果を測定する → 子どもたちが学ぶ**

これまで別々に行われていた行政の道路安全対策、学校の通学路点検、PTAの危険マップ作成、保護者からの情報提供、子どもの安全教育を一つの仕組みに統合します。

---

## 2. 解決したい社会課題

### 自治体・学校が抱える課題

柏市を例に、通学路安全対策の現状を検討しました。

柏市には「通学路交通安全対策推進会議」があり、教育委員会、学校、警察、道路管理者などが連携して安全対策を行っています。

しかし、次のような課題が考えられます。

| 課題                   | PathGuardianでの解決方法 |
| -------------------- | ------------------ |
| 危険箇所の情報が紙やExcelなどに分散 | 地図とデータベースで一元管理     |
| 学校ごとに危険マップを作成        | ボタン一つで自動生成         |
| 保護者の危険情報が行政に届きにくい    | 写真・位置情報による投稿       |
| 改善要望の進捗が分かりにくい       | ステータス管理            |
| 事故が起きてから対策することが多い    | AIで潜在的危険箇所を予測      |
| どの危険箇所から対策するか判断が難しい  | データに基づく優先順位付け      |
| 路面シールなどの対策効果が分からない   | 設置前後の行動変化を測定       |
| 子どもが危険を学ぶ機会が限られる     | ゲーム・モンスター・親子イベント   |

なお、**柏市がどこまで紙・Excelで管理しているかは、実務担当者への確認が必要**です。既存のシステムや業務フローを調べたうえで、置き換える部分と連携する部分を判断します。

# 3. これまでに考えた7つの主要機能

## ① 日本全国の交通事故危険予測AI

### 目的

**過去に事故が起きていない道路でも、事故が起こりそうな場所をAIで発見する。**

警察庁の事故オープンデータと、日本全国の地理・道路情報を組み合わせます。

分析対象として考えているのは、過去の事故地点、事故の種類、道路幅、交差点の形状、勾配、カーブ、建物による死角、信号機・歩道の有無、交通量、車の速度、学校・学区の位置、通学動線などです。

例えば、過去に事故が発生した見通しの悪いT字路について、全国から似た道路構造を持つ場所を探します。

AIが危険候補として抽出し、現地調査によって本当に危険かどうかを確認します。

### 出力イメージ

* 全国交通事故危険予測マップ
* 市区町村別危険マップ
* 小学校区別危険マップ
* 潜在的危険箇所ランキング
* 危険の理由と推奨対策

AIスコアは事故発生の確率として安易に扱わず、検証済みの根拠を添えた「点検優先度」として利用することも検討します。

---

## ② 学区・学校単位の危険情報プラットフォーム

全国の小学校区データと事故データを重ね合わせ、特定の学校区に存在する危険を自動抽出します。

例えば「柏市立第八小学校区」を選択すると、その地区の事故履歴、AI予測箇所、保護者の危険投稿、改善要望、改善済み地点などを表示します。

学校区ごとの情報を蓄積し、地域単位で比較・管理できる仕組みです。

ただし、全国の学区境界データは自治体によって公開形式や更新状況が異なるため、データ整備が必要になります。

---

## ③ 危険箇所投稿・改善管理システム

保護者、学校関係者、PTA、行政担当者が危険箇所を写真付きで投稿できる機能です。

対象となる危険は交通事故だけではありません。

**ブロック塀の倒壊リスク、伸びた草木、見通しの悪い交差点、壊れたガードレール、暗い通学路、道路の陥没、危険な段差など**も対象にします。

投稿された情報を学校区ごとの地図に表示し、改善状況を管理します。

| ステータス  | 意味           |
| ------ | ------------ |
| 新規投稿   | 投稿された状態      |
| 確認待ち   | 学校・管理者による確認前 |
| 現地確認済み | 危険内容を確認      |
| 改善要望済み | 行政等へ提出       |
| 対応検討中  | 対策方法を検討      |
| 改善作業中  | 対応実施中        |
| 改善済み   | 対策完了         |
| 経過観察   | 継続的に確認       |

改善前後の写真や対応履歴も保存します。

**危険箇所を見つけることだけでなく、実際に改善されるまで追跡できることが重要**です。

## ④ PTA・学校向け安全マップ自動生成

参考にしたのは、柏市立第八小学校のような学校が配布している通学路安全マップです。

従来は、危険箇所を調べ、地図に書き込み、写真や説明を配置してPDFを制作しています。

これをPathGuardianでは自動化します。

学校やPTAが危険情報を登録しておけば、ボタン一つで地図を生成できるようにします。

想定する出力は、学校配布用PDF、A4・A3印刷用地図、学校ホームページ用画像、スマートフォン用Webマップ、PTA活動報告書、行政向け改善要望書です。

**一度登録した危険情報を使って、翌年以降の安全マップを簡単に更新できること**も重要な価値になります。

AIによる文章作成には、日本語を自然で読みやすく整える仕組みも導入します。行政文書、保護者向け説明、児童向け案内で文体を切り替え、事実の正確性は担当者が確認します。

## ⑤ 路面シール・QRコード・音声注意喚起

### 最初の着想

危険な交差点や事故が発生した場所に、QRコードや注意表示を設置できないかというアイデアから始まりました。

当初は電柱への設置を考えましたが、危険地点に電柱が存在しない場合もあります。

そこで、**事故が起きた地点と、子どもに注意を促す地点を分ける**という考え方に発展しました。

例えば危険な交差点なら、交差点の直前ではなく、児童が安全に停止できる手前の位置に注意表示を設置します。

### 路面シール

秦野市の「とまれ」シールを参考に、AIで抽出した危険箇所に適切な路面表示を導入する構想です。

想定している表示は「とまれ」「左右を確認」「飛び出し注意」や足型マークなどです。

道路管理者や警察との協議を前提とし、危険の原因によっては除草、速度抑制、歩道整備などを優先します。

### QRコード

QRコードは危険な場所で子どもにスマートフォンを操作させるためのものではありません。

保護者や学校が後から危険理由や改善状況、安全教育コンテンツを確認する補助機能として利用します。

### お守りBot

GPSやジオフェンスなどを活用して、危険地点への接近を検知する構想です。

対応端末から「この先の交差点では立ち止まろう」といった短い音声を再生する機能を検討しています。

ただし、歩行中の端末操作を促さず、GPSの誤差、音声による注意散漫、電池消費、位置情報の取り扱いを十分に検証する必要があります。

## ⑥ キケンモンスター・親子参加型ゲーム

これはPathGuardianの教育面における大きな特徴になり得ます。

### 基本コンセプト

**「危険を発見することを、親子で楽しめる冒険に変える」**

子どもが安全について学び、保護者と地域の危険を確認する仕組みです。

例えばブロック塀の危険を題材にすると、保護者が安全な場所から写真を撮影し、AIが危険の種類を分析します。

その内容に合わせて「ブロックウォールモンスター」のような独自キャラクターを生成します。

子どもはモンスターカードを取得し、交通安全クイズやミッションを通して対処方法を学びます。

地域の危険が改善されたら、モンスターが進化・浄化する演出も考えています。

### 発展構想

写真に写る実際の通学路と、そこに潜む架空のモンスターを組み合わせた「通学路ダンジョンマップ」を作成します。

学校やPTAの行事として展開する構想もあります。

**イベント名案：「我が街のヒーローになろう！ キケンモンスターを発見せよ！」**

参加者が親子で安全を学び、地域の危険を記録し、改善要望へつなげます。

スポンサーがカードや景品、クーポンなどを提供する仕組みも検討しています。

ただし、危険な場所へ近づくことや、危険度の高い写真を撮ることに高得点を与えてはいけません。

ポイントは危険の深刻さではなく、**安全に参加したこと、正しい安全行動を学んだこと、確認済みの有益な情報を提供したこと**に与える設計が望ましいです。

また、トークンなどの経済的報酬は、児童向けサービスの安全性や法規制を確認するまで慎重に扱います。

## ⑦ 個人情報を極力持たない設計

PathGuardianでは、子どもの個人情報をできるだけ収集しない方針です。

子どもの氏名、自宅住所、日常的な移動履歴、詳細な通学ルート、顔写真などは、必要性がなければ保存しません。

写真に写る顔、車のナンバー、表札などは公開前に適切に加工し、位置情報を含むEXIFデータも除去します。

地図についても、行政内部用・学校用・一般公開用の権限を分けます。

特に、**個人の通学ルートが特定されるデータを一般公開しないこと**が重要です。

AIサービスに送信するデータも最小限とし、保存期間、アクセス制御、監査ログ、暗号化、削除機能を組み込みます。

完全に漏えいリスクをゼロにはできませんが、万一の際も被害が広がりにくい設計を目指します。

# 4. 全国の先行事例・市場調査で分かったこと

これまでの調査で、重要な発見がありました。

### AI事故予測は浜松市だけではない

| 自治体     | 主な取り組み            |
| ------- | ----------------- |
| 浜松市     | AI事故リスク分析と現地安全対策  |
| 岐阜市     | AI分析と通学路安全ワークショップ |
| 鴻巣市     | AI事故発生リスクマップを公開   |
| 香川県     | 県内の事故危険度予測マップ     |
| 泉大津市    | 通学路の潜在的危険箇所をAI分析  |
| 新居浜市    | AI事故予測の実証         |
| 松山市・愛媛県 | 3D都市モデルを用いたリスク分析  |
| 和歌山市    | 道路・建物情報による事故リスク分析 |

つまり、事故予測AIそのものは新規技術ではありません。

### AIを提供する民間企業も存在する

KDDIは「交通安全インサイト」を提供しています。

東京海上日動グループも事故リスク分析に取り組み、2025年には通学路安全点検支援システムを発表しています。

これはPathGuardianの自治体向け案件管理構想に近い重要な競合候補です。

また、MS&ADインターリスク総研は2022年に事故発生リスクAIアセスメントを販売しましたが、2025年10月31日に提供終了しています。終了理由は未確認です。

### 「とまれシール」も全国で実施されている

秦野市、高槻市、諏訪市、目黒区などで、歩行者向けの「とまれ」や足型マークの取り組みが確認されています。

ただし、導入事例があることと、事故減少の効果が統計的に証明されていることは別です。

これまでの調査では、路面表示の種類や設置場所によって、停止行動や注意の向け方が変わる可能性も分かりました。

### 市場についての結論

**「AIで危険箇所を予測するだけ」「シールを販売するだけ」「写真で道路を通報するだけ」では差別化しにくい。**

一方、AI予測・現地点検・学校の参加・改善管理・安全教育・効果測定を統合したサービスには、まだ事業機会があると考えています。

ただし、類似機能を持つ先行サービスもあるため、「日本初」「競合なし」とは判断していません。

# 5. PathGuardianのプロダクト構造

全体を4つの製品領域に整理できます。

| 製品領域                    | 主な機能                  | 主要ユーザー     |
| ----------------------- | --------------------- | ---------- |
| **Safety Intelligence** | 全国事故分析・AI危険予測・学区分析    | 自治体・研究機関   |
| **Safety Management**   | 写真投稿・改善管理・安全マップ作成     | 自治体・学校・PTA |
| **Safety Guardian**     | 個人向けマップ・QR・GPS・お守りBot | 保護者・家庭     |
| **Safety Quest**        | モンスター・カード・イベント・安全教育   | 子ども・親子・学校  |

重要なのは、これらが独立したアプリではなく、**共通の危険地点データベースでつながること**です。

例えば、PTAが投稿した危険地点が行政の改善案件になり、改善済みの情報が学校の安全マップへ反映され、その改善が子どものゲーム内にも反映される、といった連携を目指します。

# 6. 収益モデル

現時点では、自治体向けの業務支援を収益の中心とする方向で検討しています。

| 顧客       | 提供内容           | 収益モデル        |
| -------- | -------------- | ------------ |
| 自治体      | AI分析・危険管理・効果測定 | 初期導入費＋年間利用料  |
| 教育委員会    | 学校区別管理・点検支援    | 年間契約         |
| 学校・PTA   | 安全マップ生成・イベント   | 学校単位の利用料・委託費 |
| 地域企業     | 安全教育イベントへの協賛   | スポンサー費       |
| 保護者      | 家庭用安全マップ・教育機能  | 基本無料を中心に検討   |
| 道路安全関連企業 | 分析・シール設置・改善支援  | 業務連携・受託      |

自治体営業では、AIの性能だけでなく、職員の作業時間が減ること、改善状況を説明できること、予算編成に必要な資料を作れることが価値になります。

スポンサー事業については、児童の個人情報や行動データを広告目的に利用しないことが前提です。

# 7. 開発の優先順位

全機能を同時に作るのではなく、3段階に分けて進める方針です。

| 段階                | 主な開発機能                       | 目的              |
| ----------------- | ---------------------------- | --------------- |
| **Phase 1：基盤構築**  | 学区地図、事故データ、写真投稿、改善管理、PDF自動生成 | 自治体・学校・PTAの業務改善 |
| **Phase 2：AI高度化** | 潜在危険予測、類似道路分析、写真判定、自然な日本語生成  | 分析と判断支援         |
| **Phase 3：体験拡張**  | QR、路面シール、音声Bot、モンスター、親子イベント  | 現地安全対策と教育       |

まずPhase 1を実用化し、実際の学校・PTA・行政担当者に使ってもらうことで需要を検証します。

Phase 2のAIは既存技術との連携も選択肢にし、独自モデルを開発する部分を絞ります。

Phase 3ではゲームを先行させすぎず、安全面の検証を行いながら進めます。

# 8. 柏市を起点とした実証実験

最初の実証地域として、柏市を有力候補としています。

既存の通学路交通安全対策の仕組みを活用し、行政の仕事を置き換えるのではなく、今の業務を効率化する提案です。

### 90日間の実証案

**最初の30日：現状把握と地図化**

1小学校区を対象に、事故データ、既存の危険箇所資料、通学路情報を集約します。

**31〜60日：投稿・改善管理の試用**

学校・PTAなどの協力者が危険情報を登録し、改善ステータスの管理や安全マップの自動生成を試します。

**61〜90日：評価と改善**

従来の作業との所要時間比較、地図の正確性、関係者の使いやすさなどを測定し、導入可能性を判断します。

### 次の実証

行政・学校・道路管理者から協力が得られれば、路面表示などの現地対策も検討します。

設置前後の停止率や左右確認率などを測定し、対策の効果を検証する仕組みです。

# 9. 現時点での重要な未解決課題

事業化に向けて、確認すべき課題も明確になっています。

**第一に、自治体の実務です。** 柏市が現在どのような方法で通学路危険情報を集め、共有し、改善管理しているのか。実際の職員の負担を確認する必要があります。

**第二に、競合との差別化です。** 東京海上日動の通学路安全点検支援システムなどとの機能比較をさらに深める必要があります。

**第三に、AIの予測精度です。** 道路形状が似ていても、交通量や児童の通行量が異なれば事故リスクも変わります。予測結果をどのように検証するかが重要です。

**第四に、道路表示の許可と効果です。** シールを貼る場所、素材、維持管理、設置後の安全行動の測定方法を整理する必要があります。

**第五に、個人情報と児童の安全です。** 投稿写真、正確な位置情報、通学ルート、ゲーミフィケーションを安全に扱う仕組みを、初期設計から組み込む必要があります。

**第六に、収益性です。** どの組織が費用を負担し、いくらなら導入できるのか。行政調達や学校・PTAの予算構造を確認する必要があります。

# 10. 最終的な事業の方向性

これまでの議論で、PathGuardianの方向性はかなり明確になりました。

当初は、子どもが安全な通学路を確認できるWebアプリという構想が中心でした。

そこから、事故データを分析するAI、行政の改善管理、全国の学区別安全マップ、実際の道路への注意表示、親子参加型ゲームへと発展しています。

私が特に重要だと考えるのは、**PathGuardianが「危険を知らせるアプリ」で終わらず、「危険を実際に減らすための仕組み」になること**です。

そして事業の中心は、AIモデルの精度を競うことだけではありません。

学校・保護者が集めた一次情報、全国の事故・地理データ、自治体による改善記録、現地対策の効果検証をつなぎ、使い続けるほど安全対策の知見が蓄積されることにあります。

### 最終コンセプト

> **PathGuardian**
>
> 子どもたちの通学路を、事故が起きる前に守る。
>
