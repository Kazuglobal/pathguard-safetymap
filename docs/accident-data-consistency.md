# 事故データの集計・照合の契約

事故ピンと周辺集計は `accidents.repo.ts` を通して同じ事故内容コードを使う。
コード1は死亡事故。死亡事故件数と死者人数は別の値であり、明細の先頭10件から全件数を推測しない。

- 年の絞り込み・表示は `occurred_at` の日本時間の発生年を基準にする。
  `source_year` は旧取り込みでは発生年、新取り込みでは公開ファイル年を含むため、表示年として使わない。
  公開が翌年になる事故もある。NULL日時の既存行のみ、保存された年を代用する。
- 半径内判定と候補bboxは同じ球面半径で計算する。候補が上限を超えたら正確な件数を返さない。
- 集計の中心・半径・期間を応答に含め、クライアントは要求した範囲との一致を確認する。
  地図を移動しても集計中心は変わらない。GPS中心で調べる操作と地図上の地点選択を区別する。
  地図の初期表示期間は2019〜2025年、周辺集計は2021〜2025年であり、期間と絞り込み条件を見出しに別々に表示する。
  地図に見えても集計期間外の事故は周辺件数に含めない。
- 取得失敗、整合性不一致、取得中の状態をゼロ件として表示しない。新しい検索では前の地点の数値を消す。
- 明細は死亡事故を先に表示し、件数制限による省略を明示する。行ID・日時・距離・座標でピンと照合する。
- 本票の年齢区分の最小は0〜24歳なので、15歳以下の件数は判別できない。子ども0件という結論を出さない。
- 報告一覧は投稿された危険箇所の一覧であり、警察庁の事故記録とは別。フィルターによる0件は全体に報告がないことを意味しない。

## 次の取り込み・補正前の確認

`scripts/migrate/audit-traffic-source.py` はD1の読み取り専用JSONエクスポートと本票CSVを独立した解析で照合する。
不一致・元レコード不明の場合は終了コード1。年の意味が違う場合は、日時・座標・事故内容・死傷者数すべてが
一致する一意な別年の公式レコードがある場合だけ照合し、`source_year_aliases` に記録する。

本票番号は年ごとに再利用される。既存の補正SQLを年・警察署・本票番号だけで実行する前に、
必ず発生日時・位置も一致することを確認する。事故の識別を検証できない行は補正対象にしない。
本番データの再取り込み・更新は今回実行していない。

本番公開はmainのCloudflare Production GitHub Actionsのみ。事故の回帰テストを公開前の必須ステップとする。
