# 実事故・ハザード情報と連動するAR機能の拡張

作成日: 2026-10-29

改訂: 2026-10-29（第2版。レビュー結果を反映し、最新の main を前提に書き直した）

状態: 計画（第2版）・機能実装前

前提にしたコード: origin/main `9ed7ddd75`（2026-10-29）。第1版は 10/10 時点の古いブランチ（`6a3fd5f62` 起点）のコードを前提にしていた。

## 1. 確定した選択

ユーザー確認済み:

- **対象の場所**: 現在地による現地ARと、地図で選んだ地点の事前学習の両方。
- **対象の画面**: `/map` の事故の丸（事故レイヤーの丸と吹き出し）と AR だけ。
- **地図で選ぶ入口**: 既存の「地図をタップして事故を調べる」（`inspectAccidents` → `AccidentStatsOverlay`）に足す。新しい選択操作は作らない。
- **災害表現**: 想定浸水深を、画面上の高さ比較で示す学習アニメーション。道路や建物への正確な3D位置合わせは含めない。
- **現地写真**: アプリ内の専用ストリートビュー画面。

今回は作らないもの:

- `/accidents`（ランキング・地点詳細）、事故多発地点のレイヤー、`/3d-route-poc` の変更
- 内水（雨水があふれる冠水）、浸水の時間変化の再現、新しいDBテーブル、全国データの追加取り込み

## 2. 実装用プロンプト

> 最新の main を基準に、`/map` の事故の丸と AR を拡張してください。取り込み済みの実交通事故データと、公的な洪水・津波の浸水想定データを地点にひも付けて表示します。対象外の画面（`/accidents`、事故多発地点、`/3d-route-poc`）は変えないでください。
>
> 現地の AR では現在地に基づいて表示してください。地図で選んだ地点の事前学習は、既存の「地図をタップして事故を調べる」に浸水想定の欄を足して実現してください。選んだ地点を現在地と誤認させないでください。
>
> 事故は、発生年・事故の種類・距離などをアイコンと短い説明で伝えてください。文言は地図の吹き出しと同じにし、記録にない原因や衝突の状況は創作しないでください。AR では事故を投稿データに変換せず、親子学習のツアー・チェックリスト・クイズにも入れないでください。
>
> 浸水想定区域の内側では、水位線・半透明の水面・人物との高さ比較で、公表された深さの範囲を理解できる学習アニメーションを出してください。実際の到達時間・流速・流れる向きは描かず、「浸水想定を理解するためのイメージ」と明記してください。区域外には「区域外であることは安全を保証するものではありません」を必ず付けてください。「想定区域外」「未収録」「取得不能」は区別してください。
>
> 事故の丸の吹き出しと AR の事故カードに「現地の景色を見る」を付けてください。1回の操作で、アプリ内の Google 公式ストリートビュー画面を全画面で開きます。開いている間は Mapbox の地図を見せず、閉じたら元の地図または AR に戻してください。撮影位置と事故地点のずれ、撮影年月、画像がない場合を表示し、事故当時の写真ではないことを明記してください。
>
> 歩くたびにサーバへ問い合わせないでください。距離と方角は端末で計算し、通信はまとめて行ってください。既存の安全抑制・認証・公開経路は引き継いでください。詳細と完了条件はこの文書の §4〜§6 に従ってください。

## 3. 現状（origin/main `9ed7ddd75` で確認した事実）

### 事故

- データは D1 `pathguardian-traffic`。対象年は `lib/accident-stats-year-window.ts` の `ACCIDENT_DATA_MIN_YEAR`〜`ACCIDENT_DATA_MAX_YEAR`（現在 2019〜2025年）。文書やコードに年を直接書かず、この定数を使う。
- 地図の事故の丸は `components/map/accident-heatmap-layer.tsx`。取得は `GET /api/traffic-accidents/bbox`（要ログイン）で、`lib/traffic-accident-heatmap.ts` の `fetchAccidentsInBounds` が地図のフィルター付きで呼ぶ。事故レイヤーは初期状態で非表示。既定のフィルターは `DEFAULT_HEATMAP_FILTERS`（全期間・全種類）。
- 吹き出しは `buildAccidentPopupContent` で作る。「近くの報告を見る」ボタンが前例になる。表示の文言は `toPopupDisplayData`（「子ども関与（補充票確認分）」「若年者関与（24歳以下コード）」など）。
- bbox API（`lib/db/repos/accidents.repo.ts` の `accidentsInBbox`）の性質:
  - 並び順の指定がない。`limit` で絞っても近い順にはならない。
  - 上限は1万件（子ども条件は5千件）。上限に達したかどうかの印がない。
  - `date` は生の `occurred_at`（UTC 表記と +09:00 表記が混在）。`year` は日本時間に換算済み。
  - 索引は（年, 緯度, 経度）。範囲の検索では、同じ緯度帯にある全国の事故を読む。
- 地図をタップして調べる機能は `components/map/map-container.tsx` の `inspectAccidents`。`nearby` API で半径300m・直近5年を集計し、`AccidentStatsOverlay` に出す。
  - 地図で選んだ地点か現在地かを `locationSource` で区別する。
  - 「現在地で調べる」ボタンと、地図のピンとの期間の違いの注記がある。

### 浸水想定

- データは D1 `pathguardian` の `hazard_zones`（区域）と `hazard_zone_coverage`（収録範囲）。
- 判定は `lib/hazard-zone-gate.ts` の `queryHazardGateD1`。結果は `inside / outside / no_coverage / unavailable` の4つ。
  - 深さの表記は `formatHazardDepthLabel`。
  - 区域外の文言には「※区域外であることは安全を保証するものではありません」が付く（`getHazardGateMessage`）。
- 収録範囲の表にある出典の情報は、`source` と `imported_at`（取り込み日）だけ。公表日・対象年の列はない。
- **本番にデータが入っているかは未確認**（2026-08-22 の移行設計書でも未解決事項）。
- 区域の索引は（種類, 西端の経度, 東端の経度）。点の判定では、西端がその地点より西にある区域をすべて読む。

### AR

- 本体は `components/map/ar-view.tsx`。表示するのは投稿（`DangerReport[]`）だけで、`map-container` から `ARViewMode`（`nearby` / `parent_child_route`）で渡す。
- 学習ツアーは、AR に表示する項目すべてから作られる（`buildARLearningTourStops(arHazards, …)`）。子ども向けのチェックリストとクイズは、投稿から作られる。
- 安全抑制は `lib/ar-safety.ts`。位置精度50m超・速度15km/h超で、接近の強調を止める。速度が取れない端末では、速度による抑制は働かない。
- 方角が取れないとき、親子モードは AR を止める。通常モードは前方の絞り込みを外して全方向に描く（`getARVisibilityOptions`）。距離順の一覧はない。
- 親子モードで位置が取れないときは、位置を使わない「手動位置モード」になり、距離0で並ぶ。
- 表示距離は既定500m（設定で100〜1000m）。カメラは `useARCamera({ enabled })` で止めたり再開したりできる。

### ストリートビュー・公開

- 既存の部品は、`/3d-route-poc` の試作 `components/3d-route/street-view-panel.tsx` だけ。地点がないと渋谷を表示し、座標で表示し、向きは北に固定で、エラーを区別しない。**流用しない**。
- キー `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` は、ビルド時に埋め込まれる（`next.config.mjs`）。しかし本番・プレビューのワークフローはこのキーを渡していない。`env.defaults.json` は git にない。
- CSP（`lib/content-security-policy.mjs`）は全ページに効いていて、Google 地図のスクリプトと画像の配信元を許可していない。
- プライバシーポリシーの「6. 外部のサービス」（`app/privacy/page.tsx`）に、Google Maps Platform の記載がない。
- 新しいページと API は、`open-next.config.ts` の振り分けに登録が要る（`/api/hazard` は AI_VISION の Worker）。登録漏れは `tests/unit/cloudflare/open-next-split-routes.test.ts` が止める。
- 運用手順書（`docs/runbooks/cloudflare-production-cutover.md`）は Workers Free の維持を前提にしている。Free の D1 は読み取りが1日500万行までで、超えると、日本時間の朝9時に戻るまでアプリ全体の D1 が止まる。ただし 9/26 の計画書は有料プランの枠で見積もっていて、今のプランは文書からは決められない。

## 4. 実装手順

### ⓪ 着手前の確認（ここを通るまで機能の実装に入らない）

- [ ] 浸水データの収録状況を、本番 D1 で確認する（読み取りのみ。実行前にユーザーの承認を得る）。収録範囲の小さい表だけを読む。`hazard_zones` の `COUNT(*)` は全行を読むので使わない。

  ```
  npx wrangler d1 execute pathguardian --remote --command "SELECT hazard_type, region_label, source_layer, imported_features, imported_at FROM hazard_zone_coverage ORDER BY hazard_type, region_label"
  ```

- [ ] 収録が0件なら、⑤（浸水の学習）を「未収録」の表示だけで出すか、データの投入まで保留するかを、ユーザーと決める。
- [ ] Cloudflare の今のプラン（Free / Paid）を確認し、運用手順書と 9/26 の計画書の食い違いを解消する。
- [ ] D1 の読み取り行数（`rows_read`）を、本番規模のデータで測る（読み取りのみ。承認を得て実行する）。
  - 事故: AR が取る範囲の bbox。`scripts/migrate/benchmark-d1-bbox.ts` を使う。
  - 浸水: `zonesAtPoint` と同じ問い合わせ。人の多い地点（例: 東京23区）と少ない地点の両方で測る。
- [ ] 計測値から、20分歩く AR 1回で読む行数を見積もる。1日の上限に対する割合を記録し、⑥の取得間隔を決める。

**受け入れ条件**: 浸水データの有無、プラン、1回あたりの読み取り行数が記録されている。

### ① 公開の前提を整える（Google・CSP・ポリシー）

- [ ] Google Cloud で、本番用とプレビュー用のキーを分ける。
  - それぞれ、参照元（サイトの URL）と使える API（Maps JavaScript API）を制限する。
  - API ごとに1日の上限（Quotas）を設定する。予算アラートは通知するだけなので、上限の代わりにはしない。
- [ ] `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` を、本番とプレビューのワークフロー（`.github/workflows/cloudflare-production.yml`・`cloudflare-preview.yml`）のビルド環境に渡す。
  - プレビューの公開値の一覧（`scripts/cloudflare/preview-config.mjs` の `previewPublicNames`）に入れると、必須の値になる。扱いを決めてから入れる。
  - ブラウザでだけ使う値なので、Worker のシークレット（`scripts/cloudflare/deploy-free-workers.mjs` の `secretNames`）には入れない。
- [ ] CSP に、Google の Maps JavaScript API の CSP ガイドが示す配信元を足す（`script-src` など。具体的な値は、実装時に公式ガイドで確定する）。`tests/unit/lib/content-security-policy.test.ts` も直す。
- [ ] プライバシーポリシーの「6. 外部のサービス」に、Google（ストリートビューの表示）を足す。開いた地点と IP アドレスが Google に送られることを書き、改定の記録を残す。

**受け入れ条件**: プレビューでストリートビューが表示され、ブラウザに CSP 違反と認証エラーが出ない。

### ② 取得 API（サーバ）

- [ ] bbox API に、後方互換の `truncated` を足す。
  - 上限より1件多く取って判定する（`nearbyStats` の `records_truncated` と同じ方法）。
  - 既存の地図の取得（`fetchAccidentsInBounds`）は、変えずに動くこと。
- [ ] 認証必須の `GET /api/hazard/point-risks?latitude=…&longitude=…` を追加する。
  - 洪水・津波それぞれを `queryHazardGateD1` で判定し、状態・深さの範囲・区域ID・`source_layer` を返す。判定に許容幅は入れない（`toleranceMeters` は0）。
  - その地点を含む収録範囲の、地域名・出典・取り込み日も返す。これを取る関数を `hazard.repo` に足す。
  - 公表日と対象年は、コードの中に置く出典の一覧（`source_layer` → データ名・公表年・URL）から出す。一覧にないものは「不明」とし、推測で埋めない。新しいテーブルは作らない。
  - `open-next.config.ts` の AI_VISION の振り分けに、`app/api/hazard/point-risks/route` を足す。
  - レート制限には既存の `checkApiRateLimit`（ユーザーごとに60回/分）を使う。Upstash が使えないときの扱いは、既存のレート制限の方針に合わせる。

**受け入れ条件**: 同じ座標で、区域外・未収録・取得不能を取り違えない。上限に達した事故の取得を、全件として扱わない。

### ③ 地図: 事故の丸から景色を開く／タップで調べるに浸水を足す

- [ ] 吹き出し（`buildAccidentPopupContent`）に「現地の景色を見る」を足す。作りは「近くの報告を見る」と同じにする。
- [ ] ストリートビュー画面を新しく作る。試作の `street-view-panel.tsx` は、流用も変更もしない。
  - ボタンを押したときだけ、`@googlemaps/js-api-loader` で読み込む。このローダーは違う設定で作り直すとエラーになるので、試作と設定をそろえるか、読み込みを1つの関数にまとめる。
  - 事故地点から半径50m以内で、Google が撮った屋外の画像に絞ってパノラマを探す（`StreetViewSource` の指定は、公式ドキュメントで確定する）。見つかったパノラマを ID で表示し、撮影位置から事故地点を向く向きで開く。
  - 画面に出すもの:
    - 事故の情報（吹き出しと同じ文言）
    - 撮影位置から事故地点までの距離
    - 撮影年月（取れる場合）
    - 「事故当時の写真ではなく、周辺の景色です」
    - Google のロゴと著作権表示（消さない）
  - 失敗は3つに分けて出す。画像なし（50m以内にない）、キーや課金の設定不足（`gm_authFailure` で見分ける）、通信失敗。別の地点を開き直したときは、古い応答で表示を上書きしない。
  - 全画面・不透明で開き、地図を完全に隠す（地図の上に小窓で重ねない）。閉じたら、元の地図の位置と吹き出しに戻す。
- [ ] 「タップで調べる」（`AccidentStatsOverlay`）に「浸水の想定」の欄を足す。
  - 同じ中心座標で `point-risks` を呼び、洪水と津波それぞれの状態を出す。区域外には既存の注意文を必ず付ける。
  - 区域内なら、「浸水の深さを見る」で⑤のアニメーションを開く。
  - 「選んだ地点」と「現在地」は、既存の区別（`locationSource`）どおりに表示する。
  - 事故の集計（半径300m・直近5年）と、地図のピンとの期間の違いの注記は、今のまま変えない。

**受け入れ条件**: 事故の丸から1回の操作で景色を開け、閉じると元の地図に戻る。タップで調べた地点の浸水の状態が、4つを取り違えずに出る。

### ④ AR に実事故を追加

- [ ] 事故は投稿（`DangerReport`）に変換せず、事故専用の型と配列を持つ。学習ツアー（`buildARLearningTourStops`）にも、チェックリスト・クイズ（`buildKidsChecklist`・`generateKidsQuiz`）にも渡さない。
- [ ] 事故の条件は、地図のピンに合わせる。
  - 地図で事故レイヤーを表示中ならそのフィルターを、非表示なら `DEFAULT_HEATMAP_FILTERS` を使う。
  - `ARViewMode` に事故の条件を足し、`map-container` から渡す。
  - AR の画面に、期間と条件を表示する。
- [ ] 取得のしかた:
  - AR を開いたら、「表示距離＋余白」の範囲を bbox API で1回取る。距離と方角は、投稿と同じ計算式で端末で計算する。
  - `limit` では近い順を作れないので、上限で取って端末で並べる。`truncated` のときは「件数が多いため一部だけ表示しています」と出す。
  - 取り直すタイミングは⑥に従う。
- [ ] 表示:
  - 表示距離は既存の設定（既定500m・100〜1000m）に従い、近い順に最大20件を出す。
  - 50m以内では接近を強調する（安全抑制中はしない）。重なったマーカーはまとめる。
  - 投稿と見分けられる見た目にする。文言は `toPopupDisplayData` と同じにする。
  - 年は `year` を使う。日時を出すときは日本時間に直す。
  - 出典（警察庁の交通事故統計オープンデータ）と対象年を出す。加工したことの書き方は、利用条件に合わせる。
- [ ] 方角が取れないとき: 通常モードは、距離順の一覧に切り替える（新しく作る画面）。親子モードは既存どおり AR を止め、安全の方針は変えない。
- [ ] 親子モードの手動位置モードでは、事故と浸水を出さない。代わりに「位置が取れないため表示しません。地図のタップで調べられます」と出す。
- [ ] 事故カードから、ストリートビュー画面を開く。
  - AR は閉じず、AR の中の全画面のレイヤーとして出す。
  - 開いている間は、カメラ（`useARCamera` の `enabled`）と描画を止める。
  - 閉じたら再開し、選んでいた事故と学習の進み具合を戻す。

**受け入れ条件**: 実事故と投稿を見分けられる。景色を見て戻っても、学習の状態が変わらない。事故が学習の必須項目に入らない。

### ⑤ 浸水の深さの学習アニメーション

- [ ] 区域内（`inside`）のときだけ出す。
  - AR では、案内を区域ごとに1回だけ出し、自動では再生しない。立ち止まって見ることを確認したあと、「浸水の深さを見る」で再生する。
  - 「タップで調べる」の地点でも、同じ部品を使う。
- [ ] 洪水は水位が上がる表現、津波は浸水深と避難行動の説明にする。到達する波や、流れる向きは描かない。
- [ ] 深さは、公表された範囲として幅で示す（表記は `formatHazardDepthLabel`）。上限のない区分や深さ不明を、決まった数値に置き換えない。深さ不明のときは高さ比較の絵を出さず、文字だけにする。
- [ ] 洪水と津波の両方が当てはまるときは、切り替えて出す。区域外・未収録・取得不能では、アニメーションを出さない（区域外の注意文は出す）。
- [ ] 「浸水想定を理解するためのイメージです。実際の水位・到達時間・流れではありません」を常に出す。
- [ ] 一時停止と再生に対応する。動きを減らす設定（`prefers-reduced-motion`）では、動かない絵にする。
- [ ] GPS の揺れで境目の判定が変わる問題は、端末で抑える。同じ判定が2回続くまで、案内を出したり消したりしない。

**受け入れ条件**: 公的データの深さの範囲を、誤解なく確認できる。到達時間や実際の水位と誤解させない。

### ⑥ 取得の頻度・安全・公開

- [ ] 位置が更新されるたびに行うのは、端末の中の距離と方角の計算だけにする。通信は次のときだけ行う（数値は初期値で、⓪の計測で見直す）。
  - 事故: 前回取った中心から300m以上動いたとき。表示距離やフィルターを変えたとき。
  - 浸水: 前回判定した地点から50m以上動き、かつ前回から10秒以上たったとき。
  - 地点が変わったら、古い要求は中断する。
- [ ] 安全抑制（精度50m超・速度15km/h超）の間は、接近の強調と、浸水の案内・アニメーションを止める。速度が取れない端末では抑制が働かないので、浸水のアニメーションは必ず利用者の操作で始める。
- [ ] Google の画像は、保存・加工・AI生成への入力に使わない。課金のある API は、ボタンを押したときだけ呼ぶ。
- [ ] 最新の main から作業ブランチを作り、PR → CI → 隔離プレビューで確かめる。本番の公開は、main の Cloudflare Production GitHub Actions だけで行う。

**受け入れ条件**: 歩いている間、通信が続かない。⓪の見積もりで、1日の上限に余裕がある。安全抑制・認証・公開経路が保たれている。

## 6. 初期版の前提

取り込み済みのデータがある地域だけを対象にする。全国での完全な収録や、新しい年度の取り込みは今回に含めない。未収録の地域は、画面ではっきり示す。

アニメーションは、平時の防災学習のためのもの。公的な時系列データで浸水の進み方を再現するのは、別の機能として扱う。国土地理院も、浸水深の区分の情報と、時間の変化を扱う浸水ナビを区別している。[ハザードマップFAQ](https://disaportaldata.gsi.go.jp/hazardmap/faq/faq.html)

ストリートビューは、画像がある地点でだけ出す。Google の規約の本則は「Google 以外の地図と一緒に、または近くで使わない」で、例として「ストリートビューと Google 以外の地図を同じ画面に出さない」が挙がっている。全画面で地図を隠すのはこのため。規約・API の仕様・データの年度は、実装時と公開時にもう一度確かめる。[Google Maps Platform 利用規約](https://cloud.google.com/maps-platform/terms)

この文書の作成では、機能の実装・本番設定の変更・デプロイは行わない。

## 7. 推奨デフォルトで決めた点（変更可）

ユーザーに確認していない点は、保守的な選択にした。

- AR の事故の条件は、地図のピンに合わせる（「タップで調べる」の集計である、直近5年・300m とは別）。
- 方角が取れないとき、通常モードは一覧、親子モードは既存どおり停止。
- 親子モードの手動位置モードでは、事故と浸水を出さない。
- 取得の間隔（事故は300m、浸水は50m・10秒）は初期値。
- `point-risks` は、第1版どおり `/api/hazard` の下（AI_VISION の Worker）に置く。
- レート制限は、既存の汎用の制限（60回/分）。

まだ決まっていないこと: 浸水データが0件だったときの扱いと、Cloudflare のプラン（どちらも⓪で決める）。

## 8. 第1版からの主な変更

- 前提にするコードを origin/main（`9ed7ddd75`）に変えた。事故の対象年は、決め打ちの「2018〜2024年」をやめて定数を使う形にした（現在 2019〜2025年）。
