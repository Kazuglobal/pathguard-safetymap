## Context

PR #274 で main に入った AR 浸水学習（`components/map/ar-inundation-overlay.tsx`）は、画面下部の比較図の中で水面画像1枚（`public/images/ar/water-surface.png`）を CSS で上下させる方式。津波は色と点滅で強調している。人物との比較に加えて、カメラ映像を背景にした学習イメージで、公表された浸水深の範囲を理解しやすくする。

### ゴールと表現の限界

**ゴールは、仮定した水平な平面に想定浸水深の範囲に応じた WebGL の水面を置き、カメラ映像と人物の比較図を通して、深さの規模感を学べるようにすること。** 水面の揺れや映像の歪みは、理解を助ける視覚効果として扱う。

端末高を一定と仮定し、端末の傾きに合わせて水面を描く。実際の地面の検出、道路の勾配・段差、建物の形状、カメラの地面からの高さの測定は行わない。FOV も推定値を含む。このため、**「この道路のどこまでが浸かるか」「建物のこの位置まで水が来るか」を正確に再現するものではない。** 水平な仮想平面と実景の重なりが自然に見えても、現地の浸水位置を測定・予測した結果とは扱わない。

- UI の名称は「浸水深の学習イメージ」とする。「この道路の浸水を再現」「実際の浸水位置」など、現地の再現精度を約束する文言は使わない。
- 再生前と表示中に「仮定した平面に水面を重ねた学習イメージです。実際の道路・建物の浸水位置を示すものではありません。」を表示する。説明を閉じる操作や詳細表示だけに隠さない。
- 公表された深さの範囲（下限〜上限）と出典を主情報として維持する。人物や建物の高さの目安は一般的な参考であり、利用者本人やカメラに映る建物の計測結果としない。
- 現在の水位、到達時間、流れ、通行可否、避難経路の判定には用いない。既存の `HAZARD_LEARNING_NOTICE` と避難行動の案内も維持する。

### 津波の表現について（押し寄せる波を描くか）

**推奨：AR では、押し寄せる波（波の先端・決まった向きの流れ）は描かない。**

- このアプリには、波が来る向き・到達時間・流れの速さのデータがない。カメラ映像の中で「前から波が来る」と描くと、利用者がたまたま向いていた方向を「海の方向」と受け取りかねない。その結果、海の方へ逃げる誤った避難につながる危険がある。
- 代わりに、津波らしさは質感で見せる。濁った水、乱れ、泡、向きの定まらないがれき。ただし、濁りや乱れの強さも実地点の予測値ではない。出典のある事実と、既存の避難行動の文言を添える。30cm 程度の津波の危険性については、波の高さと陸上の浸水深を混同せず、実装時に一次情報に合わせて文言を確定する。
- 押し寄せる波を見せたい場合は、利用者の位置・向きと結びつかない一般的な解説（イラスト・映像）として別機能にする。計画書⑤の「到達する波・流れる向きは描かない」は維持する。

## 方式

### 1. 幾何と映像の投影（純関数）`lib/ar-water-geometry.ts` 新規

- 有効な端末の傾き（DeviceOrientation の `beta` / `gamma` と `screen.orientation.angle`）から、カメラのピッチとロールを出す。ローパスフィルタをかけ、縦持ちと横持ちの両方に対応する。
- 仮定する端末高を `AR_ASSUMED_CAMERA_HEIGHT_M = 1.4` とする。仮想平面は y = −1.4、水面は y = −1.4 + 深さ。この値は実測した目線・身長ではなく、仮想シーン内の基準である。
- 深さが仮定した端末高を超えたら、仮想視点が水面下にある表現に切り替える。全体の濁りと、視線に応じた水面の裏側を描く。「仮想視点（水面下）」と表示し、利用者本人の頭や端末が実際に水没する高さを判定したとは説明しない。深い範囲の違いは、継続表示する数値と人物の比較図で伝える。
- 範囲のキーフレーム：水位は 0 → 下限 → 少し止める → 上限（帯で示す）の順に上がる。これは深さの比較のための順序であり、実際の浸水の進行や所要時間を示さない。上限なし（`depthMaxMeters === null`）では下限まで上げ、上向きの「上限なし」表示にとどめる。有限の上限を作らない。深さ不明では水面を出さない。
- 映像の投影に、`videoWidth` / `videoHeight`、映像を表示する領域の幅・高さ、中央基準の `object-fit: cover` の切り抜き量を使う。元映像全体の水平 FOV と元映像の比率から画角を求め、切り抜き後の有効な画角を水面のカメラにも適用する。元映像の FOV を表示領域の比率だけで直接変換しない。FOV の取得元が不明な場合は推定値として扱い、実測精度を約束しない。
- 同じ画面座標→映像 UV の変換を屈折シェーダーでも使う。波による歪みをゼロにしたとき、背景と水面内の映像で同じ点が一致することを基準にする。メタデータ未取得時は描画せず、縦横切り替え・リサイズ・映像サイズ変更で投影を再計算する。

### 2. 深さの目安 `lib/hazard-depth-guide.ts` 新規

- 目盛りの候補：0.5m（大人の膝）、1.0m（腰）、2m（1階の軒下）、3m（2階の床下）、5m（2階の軒下）。実装時に国交省『水害ハザードマップ作成の手引き』などの一次情報で文言と数値を確認し、確認できた項目だけを採用する。身長や建物の構造によって異なる目安であることを添える。
- 津波の危険性に関する事実も同じファイルに置く。各項目に `sourceName` と `sourceUrl` を必須にし、出典がない文は置かない（テストで強制）。数値が波の高さか陸上の浸水深かも確認する。

### 3. 描画 `components/map/ar-water-scene.tsx` 新規

- `@react-three/fiber`（依存に入っている）の透明 Canvas を、カメラ背景の上、シートの下に重ねる。SSR を避けてクライアント部品から `next/dynamic`（`ssr:false`）で読み込む。
- 水面は ShaderMaterial で描く。手続き的な小さい波（Gerstner 風）、フレネルによる透明度、`THREE.VideoTexture` を用いた映像の歪みで表現する。現実の物体の深度や形状は取得せず、屈折は画面上の視覚効果とする。外部のテクスチャは使わない。
  - 洪水：泥色、ゆるい揺れ、水位はゆっくり上がる。
  - 津波：黒みがかった濁り、乱れと泡のノイズ、インスタンス描画の板片（がれき）。がれきは向きの定まらない揺れだけで動かし、一方向へ流さない。
- 傾きと測定時刻は ref で受け取り、`useFrame` で読む。センサー更新ごとに React を再描画しない。水位・波・がれきの時間進行には、描画用の時刻と独立したアニメーション時刻を使う。
- 一時停止はアニメーション時刻だけを止める。表示中の `frameloop` は初期版では `always` とし、停止中も姿勢と最新の映像を反映する。再開時に停止時間分の水位や波が飛ばないようにする。将来 `demand` に変える場合は、傾き・動画フレーム・投影の更新時に `invalidate()` する仕組みと検証を必須とする。[R3F公式説明](https://r3f.docs.pmnd.rs/advanced/scaling-performance#triggering-manual-frames)
- dpr は最大 1.5。`prefers-reduced-motion` では水位上昇・波・がれきを止め、上限（上限なしなら下限）の水面と範囲の帯を表示する。ライブ映像と端末の姿勢への追従は続ける。画面非表示・安全抑制・閉じたときは描画を止める。
- 映像のメタデータとフレームが利用可能になってから `VideoTexture` を作り、復帰後に映像サイズが変わる場合は作り直す。シーンを閉じる・退避する際はテクスチャ、材質、形状、独自に登録した動画フレームのコールバックを破棄する。
- WebGL 非対応・初期化失敗・描画エラー・コンテキスト喪失では水面を破棄し、既存の人物の比較図へ退避する。`Canvas` の `fallback` とエラー境界、コンテキスト喪失の検知を用意する。比較図・深さの範囲・出典・注意文・閉じる操作を維持し、失敗したシーンを自動で繰り返し起動しない。[R3F Canvas](https://r3f.docs.pmnd.rs/api/canvas)

### 4. 既存の部品への組み込み

- `hooks/use-ar-orientation.ts`：既存の方角と許可の戻り値を維持し、`beta` / `gamma` と測定時刻を持つ `tiltRef`、表示可否のための `tiltReady` を追加する。`tiltReady` は有効・無効の遷移時だけ state を更新し、許可やリスナー登録と、有効な傾きの取得を区別する。
  - `beta` / `gamma` は両方が有限の数値であることを検証する。イベント未着・null・非数値は利用しない。
  - 有効値の最終受信から `TILT_STALE_MS = 1000` を超えたら、イベントが来なくても期限切れにする。無効値の受信、無効化、非表示、再試行、リスナーの解除で有効状態とフィルタをリセットする。復帰後は新しい有効値を待つ。画面回転時は新しい画面角で再計算する。
- `components/map/ar-view.tsx` → `ar-real-risks.tsx` → `ar-inundation-overlay.tsx`：`videoRef`、傾きの値と有効状態、FOV、表示領域の情報を渡す。
- `ar-view.tsx`：現在は `object-cover` の `<video>` の上で、既存の2D Canvasにも映像全体を描き、画面へ引き伸ばしている。実事故・浸水学習モードでは背景を `<video>` に統一し、既存2D Canvasの映像コピーと描画ループを止める。他のARモードの既存描画は維持し、切り替え時の停止・再開を検証する。背景と水面で投影と切り抜きを共有する。
- `ar-inundation-overlay.tsx`：
  - 既存の出す条件を守る。区域内、`confirmed`、立ち止まりの確認、安全抑制、非表示時の停止。
  - 許可に加え、最新の有効な傾き、深さ、利用可能なカメラ映像と投影情報が揃い、WebGL が正常なときに `ARWaterScene` を出す。それ以外は比較図と理由の説明に退避する。センサーが復旧しても水位の上昇は自動再開せず、利用者の再生操作を待つ。
  - 人物の比較図は横に残し、目盛り（hazard-depth-guide）を付ける。水面下の表現中も深さの範囲を読めるようにする。
  - 再生前と表示中に「仮定した平面に水面を重ねた学習イメージです。実際の道路・建物の浸水位置を示すものではありません。」を出す。`HAZARD_LEARNING_NOTICE` は常に出す。
- `ar-risk.css`：Canvas の重なり順、水面下のときの色、目盛り。Canvas は操作を遮らず、シート・注意文・閉じるボタンを覆わない。
- 計画書 `docs/plans/2026-10-29-ar-accident-hazard-streetview-plan.md` の⑤にも、仮定した平面による学習という目的と限界を反映する。地図で選んだ地点の比較表示には、その地点の実景として現在地のカメラを重ねない。波・流れの向きを描かない条件を維持する。
