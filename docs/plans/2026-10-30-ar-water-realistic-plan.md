# AR浸水アニメーションを「カメラの地面に水を張る」リアル表現へ（計画）

- 作成日: 2026-10-30
- 状態: 計画のみ（実装は未着手）
- 関連: [AR事故・浸水・ストリートビュー計画](./2026-10-29-ar-accident-hazard-streetview-plan.md) の⑤

## Context

PR #274 で main に入った AR 浸水学習（`components/map/ar-inundation-overlay.tsx`）は、画面下部の比較図の中で水面画像1枚（`public/images/ar/water-surface.png`）を CSS で上下させるだけ。津波は色を変えて点滅させているだけで、カメラに映る道路とは関係がない。そのため「自分が立っているこの道がどこまで水に浸かるか」が実感できない。

ゴールは、カメラ映像の地面に、想定浸水深の高さで WebGL の水面を張ること。足元から周りの道路が沈んで見え、水面の下の景色は屈折して見えるようにする。公表された深さの範囲（下限〜上限）を誤解なく伝えるという原則は変えない。

### 津波の表現について（押し寄せる波を描くか）

**推奨：AR では、押し寄せる波（波の先端・決まった向きの流れ）は描かない。**
- このアプリには、波が来る向き・到達時間・流れの速さのデータがない。カメラ映像の中で「前から波が来る」と描くと、利用者がたまたま向いていた方向を「海の方向」と受け取りかねない。その結果、海の方へ逃げる誤った避難につながる危険がある。これは誇張の問題ではなく、避難の向きを誤らせる害になる。
- 代わりに、津波らしさは質感で見せる。黒く濁った水、強い乱れ、泡、向きの定まらないがれき。加えて、出典のある事実（気象庁の「浸水深30cm程度でも避難行動がとれなくなる」等。実装時に一次情報で確認）と、既存の避難行動の文言を添える。
- 押し寄せる波を見せたい場合は、AR ではなく、利用者の位置・向きと結びつかない一般的な解説（イラスト・映像）として別機能にする。計画書⑤の「到達する波・流れる向きは描かない」は維持する。

## 方式

### 1. 幾何（純関数）`lib/ar-water-geometry.ts` 新規
- 端末の傾き（DeviceOrientation の `beta` / `gamma` と `screen.orientation.angle`）から、カメラのピッチとロールを出す。ローパスフィルタをかけ、縦持ちと横持ちの両方に対応する。
- 目の高さは `AR_EYE_HEIGHT_M = 1.4`（端末を構えた高さの目安）を定数にする。地面は y = −1.4、水面は y = −1.4 + 深さ。
- 深さが目の高さを超えるときは「水中」判定にする。画面全体を濁った色にし、上方に水面を下から見た絵を描く。3m以上の区域で「頭より上まで来る」が伝わる。
- 範囲のキーフレーム：水位は 0 → 下限 → 少し止める → 上限（帯で示す）の順に上がる。上限なし（`depthMaxMeters === null`）では下限まで上げ、上向きの「上限なし」表示にとどめる。有限の上限を作らない（既存の原則と同じ）。深さ不明では水面を出さない。
- 縦の画角は、既存の `fov`（水平）と画面比から換算する。

### 2. 深さの目安 `lib/hazard-depth-guide.ts` 新規
- 目盛り：0.5m（大人の膝）、1.0m（腰）、2m（1階の軒下）、3m（2階の床下）、5m（2階の軒下）。出典は国交省『水害ハザードマップ作成の手引き』の凡例。実装時に一次情報で文言と数値を確認する。
- 津波の事実（30cm）も同じファイルに置く。各項目に `sourceName` と `sourceUrl` を必須にし、出典がない文は置かない（テストで強制）。

### 3. 描画 `components/map/ar-water-scene.tsx` 新規
- `@react-three/fiber`（依存に入っている）の透明 Canvas を、`<video>` の上、シートの下に重ねる。SSR を避けて `next/dynamic`（`ssr:false`）で読み込む。
- 水面は ShaderMaterial で描く。手続き的な小さい波（Gerstner 風）、フレネルによる透明度、`THREE.VideoTexture`（既存の `videoRef`）を UV で歪ませた屈折で、水面下の道路を沈んで見せる。外部のテクスチャは使わない。
  - 洪水：泥色、ゆるい揺れ、水位はゆっくり上がる。
  - 津波：黒みがかった濁り、強い乱れと泡のノイズ、インスタンス描画の板片（がれき）。がれきは向きの定まらない揺れだけで動かし、一方向へ流さない。
- 傾きは ref で受け取り、`useFrame` で読む。60Hz で React を再描画しないため。
- 一時停止中は `frameloop="demand"`。dpr は最大 1.5。閉じたら破棄。`prefers-reduced-motion` では波もがれきも止め、上限（上限なしなら下限）の静止した水面と帯だけにする。

### 4. 既存の部品への組み込み
- `hooks/use-ar-orientation.ts`：今は `alpha`（方角）だけを返している。`beta` / `gamma` を `tiltRef` として追加で返す（state にはしない）。
- `components/map/ar-view.tsx` → `ar-real-risks.tsx` → `ar-inundation-overlay.tsx`：`videoRef` と `tiltRef` を渡す。
- `ar-inundation-overlay.tsx`：
  - 既存の出す条件はそのまま守る。区域内、`confirmed`、立ち止まりの確認、安全抑制、非表示時の停止。
  - 方位の許可があり、深さが分かるときは `ARWaterScene` を出す。許可がないときは、今の比較図だけにする（傾きを推測で決めない）。
  - 人物の比較図は小さくして横に残し、目盛り（hazard-depth-guide）を付ける。
  - 注意文に「カメラの地面に重ねたイメージで、道路の高さや地形には合わせていません」を足す。`HAZARD_LEARNING_NOTICE` は常に出す。
- `ar-risk.css`：Canvas の重なり順、水中のときの色、目盛り。
- 計画書 `docs/plans/2026-10-29-ar-accident-hazard-streetview-plan.md` の⑤：「画面上の高さ比較」を「カメラの地面に重ねた水面＋高さ比較（地形合わせなし）」に更新する。波・流れの向きを描かない条件はそのまま残す。
