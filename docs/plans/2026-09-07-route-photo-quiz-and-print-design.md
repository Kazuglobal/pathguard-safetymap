## 2026-09-29 方針変更

現段階の完成条件は、個人のコース作成、写真クイズ、通常コースのクリア後に解放する雨・夕方・地震の学習、親子チェックシートの保存・印刷とする。以下に記載した学校内共有は当初要件として設計と実装を残すが、利用と完成判定には必須としない。学校で運用する際は、招待コードでの参加、公開・解除、別アカウントからの閲覧、権限と個人情報保護を別途実操作で検証する。

## 1. 今回つくるもの

**自分の通学路の写真で「見つける → 起こりそうなことと理由を考える → 安全な行動を選ぶ」を学ぶ短いクイズと、その学びを親子で確かめられる、読みやすい印刷物をつくる。**

World Labsによる3D生成を、新機能の作成・公開・プレイ条件から外す。写真自体が地域の現実感を担い、問題・解説・短いアニメは再利用できる教材で構成する。新機能の生成AI API呼び出しは初期版では行わない。保存・通信・既存地図サービスの運用費は別途残るため、「運営費無料」とは表示しない。

今回の対象は、提案①「通学路の写真クイズ」と、既存③「親子の通学路チェックシート」の改善。危険情報の対応管理や学校への新しい通知システムは今回の範囲に含めない。

### 引き継ぐ要件

- 小学生を中心に中学生まで。学年別の読み方・出題を自動設定し、読み上げ等は個別に変更できる。
- 複数の写真を通学順に並べる。位置情報がある場合の並べ替え補助と手動修正を残す。
- 交通、転落、水路、工事、暗い道、防犯、大雨、地震の8分類を初期の教材対象にする。
- 「写真で確かめたこと」と「もしもの想定」を明確に分ける。
- 理由を理解し、安全な行動を選べてクリア。誤答で罰や怖い映像を与えない。
- Googleログイン、学校内の共有、児童名を出さないコース名、教員による内容修正を引き継ぐ。
- 学校内への公開は、以前の合意どおり作成者のプレビュー確認と公開操作で行う。先生の承認を必須にしない。内容を修正できる先生の権限は維持する。
- 写真の顔・表札・ナンバー等を隠してから保存・共有する。現行の自動顔検出と手動修正を活用する。
- スマートフォン、学校のタブレット、パソコンに対応する。

### 今回の具体的な初期値

| 項目 | 初期仕様 |
|---|---|
| コース名 | 「学校東側コース」など、児童名や自宅住所を含めない名前 |
| コースの写真 | 1枚から開始可能、上限24枚。既存の複数地点データを保持 |
| 1回の学習 | 基本3地点。1〜2地点しかなければその数で開始 |
| 所要時間の表示 | 「3分めやす」。制限時間・時間による失敗なし |
| 学ぶ順序 | 通学順を保持して3地点ずつ。次回は未学習の地点から |
| 家庭用の紙 | A4縦・基本2ページ、今日の3地点を中心にする |
| 学校配布用の紙 | A4縦・基本1ページ、共有してよい内容だけを別ファイルで出力 |
| 印刷する地点 | 最初に3地点を提案。利用者が選択・並べ替え可能 |
| 地点が多い場合 | 本文サイズを保ってページ追加。切り捨てや自動縮小で収めない |

印刷用途については回答待ちの選択肢を確定事項として扱わず、家庭用を初期選択、学校用も選べる設計とする。2ページ／1ページは標準文字量の3地点での目安であり、上限ではない。

## 3. クイズ画面の設計

### 3.1 入口とコース一覧

「きけんハンター」に、大きな写真サムネイル付きの「通学路3分クイズ」を置く。既存の単写真ハンターと、別用途の `/route-quiz` を取り違えない説明を添える。

コース一覧は「つづきから／今日の3か所」を最上部に置き、その下に「自分のコース」「学校のコース」。検索はコース名、絞り込みは未学習・学習済み。学校の人数や児童名を前面に出さない。

各カードは写真1枚、コース名、地点数、学習進捗、主ボタン1つ。作成・編集はカードの補助操作とし、子どもが遊ぶボタンと区別する。空状態には写真の追加方法と、写真の不要な一般教材の入口があれば既存機能へ案内する。実在の自分の通学路でないサンプルを、自分のコースとして表示しない。

### 3.2 1地点の流れ

1. **見つける**: 大きな写真で、気をつけたい場所をタップする。
2. **考える**: 「どうして気をつける？」または「何が起こりそう？ なぜ？」に答える。
3. **選ぶ**: 「どうすると安全？」に答える。
4. **確かめる**: 短い説明と、止まる・離れる等のやさしいアニメを確認する。

3地点なら基本は写真上の探索3回と選択問題6問。低学年の読み上げや考える時間を優先し、3分に収めるために説明を飛ばさせない。実際の利用テストで長すぎる場合は、問題の意味を削る前に文章と操作数を見直す。

```text
スマートフォン・見つける画面
┌────────────────────────────┐
│ もどる    学校東側コース       音声 │
│ きょうの 1 / 3 か所    見つける     │
│                                  │
│ 気をつけたい ところを             │
│ 写真で さがそう                   │
│ ┌──────────────────────────────┐ │
│ │                              │ │
│ │      通学路の写真を大きく      │ │
│ │  正解の印は、まだ表示しない    │ │
│ │                              │ │
│ └──────────────────────────────┘ │
│ 写真を大きく見る                  │
│                                  │
│ [ヒントを聞く]  [場所を選んで答える]│
└────────────────────────────┘

考える画面：写真は参照用に残し、問いは1つ
┌────────────────────────────┐
│ 1 / 3 か所             考える      │
│ [写真 + 見つけた場所の輪郭]        │
│ どうして 気をつける？       読む   │
│                                  │
│ [A  かべの向こうが見えにくいから]  │
│ [B  いつも通っている道だから    ]  │
│                                  │
│                  [これにする]    │
└────────────────────────────┘
```

これは情報の優先順位を示すワイヤーフレーム。実際の写真寸法に合わせて高さを変え、低い画面では自然に縦スクロールする。全内容を1画面に押し込めない。

### 3.3 読みやすさ・操作の具体値

| 項目 | 採用する設計値・動作 |
|---|---|
| 本文 | 子どもの問題・選択肢18〜20px、保護者向け操作16px以上 |
| 見出し | スマホ24〜28px、PC28〜32pxを目安。長文は自然に改行 |
| 行間 | 本文1.6〜1.8。ふりがなと上下の文字が衝突しない |
| 選択肢 | 1列。全体が押せる。高さ最低56px、間隔12px。長文時は高さが伸びる |
| 補助ボタン | タップ領域最低44×44 CSS px。読み上げはアイコンと文字の両方 |
| 写真 | `object-contain`で全体を表示。正解箇所を勝手に切り抜かない。拡大できる |
| 色 | 白系背景、濃い文字、主操作に既存のブランド色。本文に薄い灰色を使わない |
| 選択・正誤 | 色に加えて輪郭・記号・「選んだ答え／もう一度」等の文字で示す |
| 問い | 一度に1つ。見つける段階で答えや正解ピンを出さない |
| 下部操作 | 次へは1つ。固定する場合は本文の末尾余白と端末のsafe areaを確保 |
| 動き | 2〜4秒程度、再生し直せる。減らす設定では静止図と文章へ切り替える |
| 読み上げ | 初回のユーザー操作から開始。次の問いで前の音声を止める。再生・停止・もう一度 |
| フォーカス | キーボード操作可能。問題切替で見出しへ移動し、フィードバックを通知 |

文字と背景のコントラストは通常文字4.5:1以上を合格条件にする。[W3Cのコントラスト解説](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)に基づく。44pxは子ども向けの独自最低値として採用し、[W3CのTarget Size (Enhanced)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)も参照する。これら一部の基準の達成だけでWCAG全体への適合を宣言しない。

通常の操作画面は320 CSS px幅でも横スクロールなしで利用できること。200%文字拡大でも情報・操作を失わない。地図や用紙の原寸プレビューには拡大・移動を用意する。[W3CのReflow解説](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)を検証時の参照にする。

### 3.4 写真上の正解と代替操作

- 作成者が写真の中の対象を長方形で囲む。保存座標は画像に対する0〜1の比率。画像の回転・マスク処理後の寸法を基準にする。
- 既存のメモの点は編集時の目安に使用し、自動で正解領域に確定しない。
- 写真表示の余白、拡大、端末回転を考慮して座標を変換する。細い対象は見える輪郭とは別にタップ許容域を設ける。近接領域が重なる場合は選択確認を出す。
- 外れた場所を押しても即「そこは安全」と言わず、「ほかにも気になるところがあるかな」と返す。出題範囲外の危険を否定しない。
- 「場所を選んで答える」では、写真上の複数の番号付き候補を同じ大きさで提示し、キーボード／読み上げでも選べるようにする。正解だけに目印を置かない。
- 視覚情報の利用が難しい場合は、確認済みの場面説明から理由・行動を学べる。記録は「場面説明で学習」とし、写真の危険を自力で発見したことにはしない。

### 3.5 写真で分かることと想定の区別

表示は次の2項目を隣り合わせにせず、短いラベルと本文で分ける。

- **写真でたしかめたこと**: 例「角にかべがあり、その先が見えにくい」。作成者の確認と根拠を保存。
- **もしものお話**: 例「その向こうから自転車が来たら？」。写真に写っていない出来事として提示。

「写真から事故が予測された」「この道は安全」のような断定をしない。写真にない水路や工事を、実在の地点の特徴として付け足さない。8分類を用意しても、各コースにはその場所に合う問題だけを設定する。

夕方・大雨・地震は条件を文章と記号で切り替える。実写真を暗く塗って見づらくしたり、災害合成を実際の被害として見せたりしない。仮想の車・矢印等を重ねる場合は「もしも」の表示を維持する。

### 3.6 学年・結果・継続

| 学年 | 標準設定 |
|---|---|
| 小1〜2 | やさしい言葉、ふりがな、音声開始を大きく案内、2択、危険1つずつ |
| 小3〜4 | 必要なふりがな、2〜3択、出来事と理由を結びつける |
| 小5〜6 | 3択、複数の動きや見通しを含む判断。文章量は増やしすぎない |
| 中1〜3 | 3択、判断の根拠と条件の違い。必要なら追加の発展問題を選べる |

学年だけを理由に音声やふりがなを強制的に消さない。初期値は自動設定し、いつでも変更可能にする。既存ファイル間で異なる低学年の境界を、新しいクイズではこの表に統一する。

誤答後は理由を短く説明し、再挑戦できる。正答と解説を確認してから本人が次へ進む。発見だけ・ボタンを押しただけではクリアにしない。初回回答、ヒント使用、最終的な理解を区別して記録する。

終了時は点数を大きく競わせる画面ではなく、「今日たしかめた3つ」と次の安全行動を表示。「つづきの3か所」「親子で確かめるシート」の2つを用途別に案内する。通常コースの全対象地点を終えたら、作成者が確認済みの「雨の日」「夕方」「地震」の問題を解放する。未作成のシナリオは空のステージを解放しない。

## 4. コース作成のUI

作成画面は、子ども・保護者・教員が下書きをつくり、作成者が確認して学校内へ共有できる形にする。先生の追加確認を公開の必須条件にはしない。

| 手順 | 操作 | その場で見える結果 |
|---|---|---|
| 1 写真をならべる | 1〜24枚追加、通学順に変更、不要な写真を除外 | 大きめのサムネイル、地点番号、保存状態 |
| 2 写したくないものを隠す | 顔の自動検出を確認、表札・ナンバー等を手動で追加修正 | 拡大可能な処理後写真、未確認の枚数 |
| 3 問題をつくる | 1枚につき基本1つの主題を囲み、分類と教材を選ぶ | 子どもに出る問い・選択肢・解説の試し表示 |
| 4 ためして共有する | 3地点を通して試す、公開前の内容確認 | 準備完了／直す場所、学校内共有の範囲 |

作成者に長文を一から書かせず、8分類の確認済みテンプレートを選び、場所に合う根拠を短く補う。自由記述だけを自動で正解問題に変換しない。テンプレートに合わない場合はメモとして残し、問題に含めない。

写真間の位置情報は順序の提案に使用し、通行可能な道の自動推定とは表示しない。位置情報のない写真も取り込める。自宅付近の除外を確認でき、位置情報は画像から除去した上で保存する。

現行は表札・ナンバーの自動検出まで実装されていない。最初の実用版では自動顔検出＋全対象の手動確認で共有可能にする。自動マスキングの追加は、精度・端末負荷・ライセンスを評価する別作業とし、「自動ですべて隠せる」と表示しない。

編集中の保存状態を「保存中／保存しました／保存できませんでした」で示し、失敗した入力は画面に残す。写真や問題を変更すると学校共有を下書きへ戻し、再確認後に公開する。別の利用者が先に編集した場合は、差分を失わず再読み込みを案内する。

## 5. 印刷するまでのUI

入口の表示を「親子チェックシート」に統一する。既存ルートカードの出力ボタンと、クイズの結果・コース詳細からアクセスできる。ファイル形式より先に、用途と掲載内容を選ぶ。

```text
PC／タブレット横：設定と仕上がりを並べる
┌────────────────────────────────────────────────────────┐
│ 親子チェックシート                            閉じる      │
│ ① 用途を選ぶ → ② のせる内容 → ③ 仕上がり確認              │
├───────────────────────┬────────────────────────────────┤
│ 家庭でつかう / 学校で配る │ A4たて・2ページ                  │
│                        │ [前]     1 / 2     [次] [拡大]   │
│ きょうの3か所           │ ┌──────────────────────────┐   │
│ ☑ 1 学校東の曲がり角    │ │                          │   │
│ ☑ 2 水路のそば          │ │ 実際と同じページ割りの紙面 │   │
│ ☑ 3 公園前の交差点      │ │                          │   │
│ [上へ] [下へ]           │ └──────────────────────────┘   │
│ 写真・地図・学年の設定   │ 写真が1枚ありません [直す]       │
├───────────────────────┴────────────────────────────────┤
│ 3か所・2ページ               [PDFを保存] [印刷する]       │
└────────────────────────────────────────────────────────┘
```

スマホはほぼ全画面のシートで1手順ずつ表示する。プレビューは「用紙全体」と「内容を読む」を切り替えられ、縮小された紙だけを読ませない。戻っても選択を失わない。危険名・説明を省略表示だけにせず、展開して全文を確認できる。

### 掲載内容の選択

- 初期は通学順の3地点を候補にする。「最も危険な3地点」とは表現しない。クイズから開く場合は今回学習した地点を選ぶ。
- 地点の選択・解除・並べ替えで、地図、写真、チェック項目の番号を同時に更新する。
- 表示する写真は加工済みであることだけを安全確認と同一視せず、共有前のマスク確認状態を示す。学校用は確認済みデータだけを採用する。
- 家庭用・学校用切替で、含まれる情報とプレビューが同時に変わる。学校用へ元の写真・自由記述・家庭用ページを混ぜない。
- 学校用の地図は共有区間を選んだ場合だけ付ける。自宅ピンを消すだけでなく、線・範囲・説明に自宅付近が残らないようにする。未設定なら地図なしで出力可能。
- 写真がなくても地点名・行動・記入欄で作成できる。地図の取得に失敗しても、地図なしの選択で続行可能にする。
- 既存のPNG/JPEGは「その他の保存方法」に移動。大量の地点を1枚の長い画像へ連結しない。

### 状態の見せ方

| 状態 | 表示と操作 |
|---|---|
| 読み込み中 | 内容の形を保つ仮表示と「通学路の情報を読み込んでいます」 |
| 0地点 | 「掲載する地点がまだありません」。選択へ戻る。安全の証明としない |
| プレビュー準備中 | ページの枠を維持。設定の版と一致するまで出力ボタンを保留 |
| 写真取得失敗 | 該当地点を示し「写真なしで作成／再読み込み」を選べる |
| 地図取得失敗 | 「地図なしで作成／再読み込み」を選べる |
| 出力中 | 二重実行を防ぎ、処理中の段階を短く表示 |
| 出力失敗 | 設定は保持し、直前の仕上がりから再試行できる |

## 6. 紙面の設計

### 6.1 すべての用紙に共通する条件

| 項目 | 仕様 |
|---|---|
| 用紙 | A4縦210×297mm。初期余白12mm、内容領域186×273mm |
| 本文 | 子どもが読む本文14pt以上、保護者向け補足12pt以上 |
| 見出し | 主見出し20〜24pt、地点見出し15〜16pt |
| 補助情報 | 日付・ページ番号等だけ10pt以上。大切な行動をここへ置かない |
| ふりがな | 原則8〜9pt以上を目安に別計測。本文との間隔を確保 |
| 行間 | 1.5〜1.7を基本。ふりがな・手書き欄を含めて実測 |
| チェック欄 | 約6×6mm、濃い枠線。1項目ずつ独立 |
| 記入欄 | 行の高さ8mm以上。日付と親子の気づきを書ける |
| 線と背景 | 白地、濃い文字、0.3mm以上を目安に枠線を実物確認 |
| 番号 | 地図・写真・説明・チェック欄で同じ番号と地点名 |
| 改ページ | 見出しだけ残さない。写真と説明、チェック欄を途中で切らない |
| フッター | 作成日、ページ番号、必要な場合は内容の確認日を区別して表示 |

数値は今回の設計基準であり、印刷物の法定基準や実測済みの結果ではない。コピー機で白黒にしても意味が通るか、原寸で検証する。

### 6.2 家庭用：基本2ページ

**1ページ目「道と、今日たしかめる3か所」**

```text
┌────────────────────────────────┐
│ 親子でたしかめる 通学路          │ 約25mm
│ 学校東側コース / 日付記入欄       │
├────────────────────────────────┤
│                                │
│  大きな地図                     │ 約90mm
│  通学路の線と 1・2・3 の目印      │
│                                │
├────────────────────────────────┤
│ 1 曲がり角   今日たしかめること   │
│ 2 水路のそば 今日たしかめること   │ 約75mm
│ 3 公園の前   今日たしかめること   │
├────────────────────────────────┤
│ 親子で歩く前に                   │ 約35mm
│ 時間・天気 / 保護者向けの短い案内 │
├────────────────────────────────┤
│ 作成日                 1 / 2    │ 約10mm
└────────────────────────────────┘
```

**2ページ目「写真で話して、行動をたしかめる」**

```text
┌────────────────────────────────┐
│ 今日の3か所を たしかめよう        │ 約20mm
├────────────────────────────────┤
│ 1 曲がり角                       │
│ [写真 約50×32mm]  気をつける理由 │ 1地点
│                    安全な行動   │ 約65mm
│ □ 話せた  □ 一緒に確かめた       │
├────────────────────────────────┤
│ 2 水路のそば  （同じ構成）        │ 約65mm
├────────────────────────────────┤
│ 3 公園の前    （同じ構成）        │ 約65mm
├────────────────────────────────┤
│ 親子で気づいたこと ____________  │ 約20mm
│ 作成日                  2 / 2   │ 約10mm
└────────────────────────────────┘
```

高さは余白を除いた領域に対する初期配分。本文の行数とふりがなで超える場合は次ページへ移す。写真は全体像を優先し、対象が小さいときは別の拡大図を追加する。拡大図だけで道との関係が分からなくならないようにする。

4地点以上を選んだ場合は3地点単位の詳細ページを増やす。1ページ目の索引が収まらない場合も続きを作る。ページ数と内容は出力前に表示する。

### 6.3 学校配布用：基本1ページ

**「みんなでたしかめる 学校東側コース」**を表題にし、児童名・自宅住所・個人のコメント・家庭用の写真を初期状態で含めない。

- 表題・コース名・確認日: 約25mm。
- 共有区間の地図: 最大75mm。共有区間が未指定なら省略し、チェック欄を広げる。
- 3地点の「場所／気をつける理由／安全な行動／チェック欄」: 各40mm程度。
- 一緒に考える短い問いと記入欄: 約30mm。
- ページ番号等: 約10mm。

学校用のために整えた短い文を使う。元データの長文を末尾で切ることや、字体を小さくすることはしない。収まらなければ2ページになることを明示する。写真付きの学校配布テンプレートは、初期の文章・地図版を検証後に追加を判断する。

QRコードは初期版に必須としない。後から付ける場合もログインを必要とするコースURLだけとし、画像の署名URL・学校参加コード・児童識別情報を含めない。

## 7. 実装上の方針

### クイズ

- 現在のコース保存・写真配信・学校の権限制御を再利用する。
- `photo-quiz-v1` と旧3D形式を明示して扱い、写真の準備完了を3Dアセットの完成状態と混同しない。
- 正解と解説の原本はサーバー側の教材として保持。子どもの取得データにはその問題に必要な問いと選択肢だけを返す。
- 1回の学習は開始時に対象・学年・問題順・版を固定する。問題ごとの途中経過を保存し、通信再試行で回数を増やさない。
- 旧3Dコースは写真とメモを引き継いだ下書きへ移行できる。正解領域・教材適合性は確認が必要。旧クリアを新クイズのクリアへ自動変換しない。
- 新規3D生成はサーバーで停止する。ボタンを隠すだけで課金APIが呼べる状態を残さない。

### 印刷

- 既存のルート＋危険投稿と、新しい写真コースは別のデータ構造のまま維持し、共通の印刷用データへ変換する。
- 用途に応じた情報の除外を先に行い、その後でプレビューと出力を作る。家庭用のDOMをCSSで隠すだけの学校用PDFにしない。
- **同じページデータ・同じ紙面DOM**をプレビュー、ブラウザ印刷、PDFダウンロードに使用する。
- ブラウザ印刷は印刷用CSSで本文テキストを保持する。既存のPDFダウンロードは互換性のために維持し、ページ単位のhtml2canvas＋jsPDFへ変更する。
- ダウンロードPDFは初期版では画像ベースであることを認識し、検索可能・アクセシブルなPDFとは表現しない。画面の「内容を読む」は通常のHTMLで提供する。
- A4ページ全体を生成する前に項目を配置し、巨大な画像を後から輪切りにする方式をやめる。写真・地図・フォントの読込後にページ数を確定する。
- クイズプレイには印刷ライブラリや3Dライブラリを読み込ませない。印刷機能を開いたときに必要な処理を読み込む。

## 8. 完成とみなす条件

### クイズの検証

- 360px幅、375px幅、390px幅、iPad縦横、PCで実際に1コースを完走できる。
- 320px幅・200%文字拡大でも、選択肢と次の操作が欠けない。操作UIの横スクロールなし。
- 縦写真・横写真・横長写真、回転後の写真、拡大後、端末回転後でも正解領域がずれない。
- 正解の表示前後で出典ラベルと写真の対応が保たれる。写真にない危険を事実として出さない。
- 誤答・ヒント・戻る・途中終了・再開・通信再試行・コース更新・共有解除を確認する。
- 小1〜2の設定で2択と読み上げ、中学生設定で理由の判断が動く。
- 第三者の学校や未公開コースの写真・学習記録を取得できない。
- クイズを何度プレイしてもWorld Labsや生成AIへの通信が発生しない。

### 印刷の検証

- 0／1／3／8／20地点、長い日本語、ふりがな、写真なし、地図なし、読込失敗で確認する。
- 家庭用と学校用を別々に出力し、学校用の全ページ・データに家庭向け情報が混ざらない。
- 地図・カード・チェック項目の番号が一致し、選択や並べ替え後も一致する。
- 実際のPDFの全ページで文字欠け・途中切断・重複・無意味な空白ページがない。
- 原寸A4、白黒、一般的なプリンター余白で、本文とチェック欄が読めて書き込める。物理印刷ができない実装環境では未確認と明記し、原寸PDFによる確認と混同しない。
- プレビューのページ数・順序・内容がPDFと一致する。PDF保存と印刷の両方を確認する。
- 標準3地点・2ページの写真入りPDFは5MB以下を性能目標とし、画質と端末メモリを測定して調整する。文字サイズを下げて容量を減らさない。

### 利用者に確かめること

最初の操作可能な版で、低学年の子どもと保護者、教員、中学生相当の読み方を確認する。子どもが説明なしで次の操作を見つけるか、紙を見て写真と場所を結びつけられるかを観察する。利用者テストを実施できていない場合は、実施済みと報告しない。

「徹底的に見やすい」の合格は見た目の印象だけで判断せず、上記の寸法、状態、端末、実出力の証拠と合わせて判断する。
